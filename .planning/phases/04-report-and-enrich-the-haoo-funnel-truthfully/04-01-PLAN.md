## Module placement decision — typed report modules under `src/`, credentialed CLI under `scripts/`

Recorded here because it is a deviation-shaped choice that a reader will otherwise re-litigate.

**Decision.** The report domain, validator, renderer and orchestrator are TypeScript modules under
`src/reporting/`, exactly as `04-PATTERNS.md` maps them (`src/reporting/haoo-report.ts`,
`src/reporting/stats-response.ts`). Only `scripts/generate-haoo-report.mjs` — the one module that
touches a credential — stays a `.mjs` Node script, also exactly as `04-PATTERNS.md` maps it.

**Why not untyped `scripts/report/*.mjs`.** `tsconfig.app.json` sets `include: ["src"]` with
`strict: true` and no `allowJs`, so a `.mjs` module imported from `src/test/haoo-report.test.ts`
raises TS7016 and `npm run typecheck` fails — and typecheck exit 0 is an acceptance criterion of both
tasks below and of 04-03 and 04-05. `eslint.config.js` scopes its rule set to `**/*.{ts,tsx}`, so
those same modules would additionally be parsed but never rule-checked while `npm run lint` is
asserted as a gate. Placing them under `src/` fixes both at once and costs nothing.

**What this buys beyond compliance.** The event label and stage maps become
`Readonly<Record<HaooMeasurementEvent, ...>>` keyed off the Phase 3 closed tuple, per the
`04-PATTERNS.md` locked-copy constant pattern. An added or removed event is then a *typecheck*
failure, not merely a test failure — a strictly stronger exhaustiveness guarantee than the plan
previously had.

**How the `.mjs` CLI reaches the `.ts` modules.** Node strips TypeScript natively (default from
22.18.0 / 23.6.0), so `scripts/generate-haoo-report.mjs` imports `../src/reporting/generate.ts` by
explicit extension. Verified locally on Node v24.12.0: the import ran with exit 0 and empty stderr,
`tsc --noEmit -p tsconfig.app.json` exited 0 with `.ts`-extension imports (`allowImportingTsExtensions`
is already true), `eslint` exited 0 over the new `src/reporting` files, and Vitest resolved the same
imports. This is why `package.json` gains an `engines.node` floor and Task 1 carries a matching
`<precondition>`.

**Cost this imposes.** Two constraints follow and are carried into the task actions rather than left
implicit. First, `src/reporting/*.ts` must import each other with explicit `.ts` extensions and must
use erasable syntax only — `import type` for type-only imports, no `enum`, no `namespace`, no
parameter properties — because Node strips types without resolving them. Second, `src/reporting/`
files join `BUILD_INPUTS` in `src/test/build-output.test.ts`, so any suite touching build freshness
must build first.

**Provider literals stay out of `src/`.** 04-05 Task 3 adds a source scan asserting no file under
`src/` contains an analytics origin literal. `src/reporting/generate.ts` therefore holds no endpoint
URL, no query path, and no credential variable name: `scripts/generate-haoo-report.mjs` owns all
three and passes them in through the injected `query` capability. The move strengthens that
invariant instead of weakening it.
