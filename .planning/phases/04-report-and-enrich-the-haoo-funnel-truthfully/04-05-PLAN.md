<objective>
Put a real, deliberately configured privacy-first analytics sink behind the measurement seam Phase 3
built, so the report in plans 04-01 and 04-03 can carry live aggregate counts — without changing what
the seam is allowed to carry.

**As a** HAOO product owner, **I want to** have the ten allowlisted HAOO events actually recorded
somewhere I can query, **so that** the funnel report shows real activity instead of an empty document.

Purpose: MEAS-01 cannot produce live counts without a provider. MEAS-08 requires that adding one
changes nothing about what the seam carries — still bare names, still no properties, still no
identity. MEAS-07 is already Complete from Phase 3 and is not re-delivered here; this plan only
guards it, because adding a real provider is the change most likely to regress the journey working
when analytics is absent or blocked.
Output: a widened fail-closed provider resolver, an injectable provider adapter, the re-scoped static
boundary, and the documentation that keeps the credential boundary explicit.
</objective>
