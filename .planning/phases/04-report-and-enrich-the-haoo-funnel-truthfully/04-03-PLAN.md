<objective>
Dress the proven report path into the full UI-SPEC Surface A document: the native period control, all
four pre-rendered period sections, collapsed stage cards with event tables in labelled scroll
regions, the always-visible caveat block, the empty-period state, and print rules — with no script,
no external resource, and no vocabulary that overstates what a browser observed.

**As a** HAOO product owner, **I want to** switch between 7-day, 30-day, 90-day and all-time views
and expand any stage to see the separate actions inside it, **so that** I can read the counts at the
level of detail I need without the document implying anyone progressed through a funnel.

Purpose: 04-01 proved the path with one period and a minimal document. This plan delivers D-01
through D-04 and the whole Surface A contract, and pins MEAS-08 with a vocabulary contract that runs
over the document's rendered text.
Output: the complete `renderReport` implementation and its contract suite.
</objective>

Complete `renderReport` against the whole of UI-SPEC Surface A. The renderer stays pure: it receives
a finished model from `generate.mjs` and returns a string. It performs no arithmetic beyond choosing

Document order, exactly as locked: h1 `HAOO funnel report`; the metadata line stating generation
timestamp, reporting timezone, analytics provider configuration state and site scope; the reporting
period fieldset with legend `Reporting period` and the four radio labels `Last 7 days`,
`Last 30 days`, `Last 90 days`, `All time` with `Last 30 days` checked; four period sections; the
caveat block last and outside every collapsible element.

Period switching carries no script. Give each period section a stable id and each radio a matching
value, then use a `:has()` rule on the document root that exposes only the section matching the
checked input. The degradation contract is load-bearing: when `:has()` is unsupported the default
must be all four sections visible in sequence under their own h2 headings. Achieve that by writing
the rule as "hide the non-selected sections when the root has a checked input", so a browser that
cannot evaluate `:has()` applies no hiding at all. Never use a `hidden` attribute, an inline display
rule, or markup omission to hide a section.

Each period section renders an h2 naming the period and its exact inclusive start and end dates, then
the comparison line `Compared with the previous {N} days, {start} to {end}.` for the three bounded
periods, or the authored all-time sentence for the all-time section. Then the four stage cards in the
locked order Discovery, Brochure interest, Qualification, Assisted and self-onboarding.

Each stage card is a native details element, collapsed by default so the opening view stays compact
per D-02 while the expanded table preserves each observable action separately rather than collapsing
their meaning. The four stages appear in the locked D-01 order as a reporting hierarchy, never as
evidence that the same browser flowed from one to the next. Its summary is its first child
and holds an h3 stage label, the stage total in the authored `{N} recorded actions` form with the
singular form when the total is 1, and the change value from `deltaLabel` (omitted in the all-time
section). Inside, the stage clarifier paragraph, then a table wrapped in a container carrying
`role="region"`, `tabindex="0"` and an accessible name referencing the stage heading id. The table has
a caption naming the stage and period, a header row of column-scoped headers `Recorded action`,
`This period`, `Previous period`, `Change`, and one row per event with a row-scoped header carrying
the literal event label. The all-time table renders only `Recorded action` and `All time`. Every
event row for the stage renders, including rows whose count is zero. An event identifier such as the
raw goal name is never rendered.

The empty period state uses the authored heading and body with `{start}` and `{end}` interpolated;
the stage cards still render with their zero values beneath it. A zero period is never a blank
section, a dash, or a hidden section.

Write the inline style element as literal CSS custom properties reproducing the inherited scale
exactly: the eight spacing values, the four type sizes with their weights and line heights, and the
colour roles from the UI-SPEC Color table. Use the system font stack, not a web font. Set
`font-variant-numeric: tabular-nums` on every count and change cell. Cap the content measure at 880px
and centre it. Give every interactive target a minimum 44px height. Add the focus-ring pairing as a
literal rule. Add a `@media print` block that hides the period control chrome and keeps the header
metadata and the caveat block. Add a `prefers-reduced-motion` block that removes the optional hover
and focus colour transitions.

Render nothing that encodes a count as a shape: no bar, gauge, donut, sparkline, arrow, chevron,
tapering silhouette, or width proportional to a value. Change values are never coloured — an increase
and a decrease both use the same secondary colour. Direction is carried by the sign and the words
only.

Extend the model built in `generate.mjs` with whatever the renderer now needs — per-period start and
end dates, the previous-period dates, the all-time first recorded day or its absence, the timezone
string, the provider configuration state, and the generation timestamp — computed in `generate.mjs`,
not in the renderer.
