## Reporting Experience

### What should the product owner see first?

| Option | Description | Selected |
|--------|-------------|----------|
| Staged funnel with counts | Discovery → brochure interest → qualification → assisted/self-onboarding; makes relationships understandable while keeping numbers literal. | ✓ |
| Headline event totals | Simple grid of individual event counts; transparent but does not communicate relationships between steps. | |
| Trend chart first | Leads with activity over time; potentially less useful while launch traffic remains low. | |
| Other | User-provided opening view. | |

**User's choice:** Staged funnel with counts
**Notes:** The staged view is a reporting hierarchy, not proof of person-level progression.

### Within each funnel stage, how much detail should be visible?

| Option | Description | Selected |
|--------|-------------|----------|
| Stage total with expandable event breakdown | Compact overview with separate preview/open/download and WhatsApp/phone/email details available on demand. | ✓ |
| Every event shown separately | Maximum transparency, but creates a dense ten-step main view. | |
| One combined count per stage | Easiest to scan, but hides which brochure or contact actions visitors chose. | |
| Other | User-provided grouping. | |

**User's choice:** Stage total with expandable event breakdown
**Notes:** Literal event meanings remain accessible beneath the compact stage presentation.

### Which time controls should the funnel provide?

| Option | Description | Selected |
|--------|-------------|----------|
| 7 days, 30 days, 90 days, and all time | Useful at launch and at low volume; bounded periods compare with their preceding equivalent periods. | ✓ |
| 30 days and all time only | Simpler but weaker for checking recent campaigns or changes. | |
| Custom date range | Flexible but more complex and may invite over-reading small samples. | |
| Other | User-provided periods or comparison style. | |

**User's choice:** 7 days, 30 days, 90 days, and all time
**Notes:** Use equivalent previous-period comparisons for bounded ranges.

### How should the report handle conversion rates without visitor or session IDs?

| Option | Description | Selected |
|--------|-------------|----------|
| Counts and period changes only | Avoids implying that anonymous aggregate events belong to the same people. | ✓ |
| Clearly labelled activity ratios | Ratios of aggregate events with an explicit non-cohort warning. | |
| Standard funnel percentages | Familiar but misleading because person-level progression cannot be established. | |
| Other | User-provided relationship between counts. | |

**User's choice:** Counts and period changes only
**Notes:** No conversion percentage is displayed without cohort evidence.
