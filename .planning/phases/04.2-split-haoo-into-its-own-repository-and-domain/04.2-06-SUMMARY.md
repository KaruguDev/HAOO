# Phase 04.2 Plan 06: Reduce ZERO-PAPER HUB to Itself Summary

**Thirty-nine HAOO files deleted by an ordinary commit, the build-time coupling replaced by an inline card record linking to `www.haoo.online`, the analytics SDK removed from both manifests, and every inventory that named a removed file narrowed in the same commit — suite green at 3 files / 28 tests, deployed green with no vendor chunk.**

## Accomplishments

The ZERO-PAPER HUB tree now contains no HAOO source, no measurement or reporting module, no
ingestion-host configuration, no analytics dependency and no measurement build variable. Thirty-nine
files left by `git rm` — D-02's ordinary deleting commit, never a rewrite — and every one was
confirmed present in `KaruguDev/HAOO` at its expected path first, with the four brochure assets
additionally confirmed byte-identical by SHA-256 before being let go.

The build-time coupling is severed. `src/products/registry.ts` holds an inline `ProductCard` record
with a locally declared type and an absolute link to `https://www.haoo.online/`. D-06's accepted
cost is written into the record's doc comment rather than mitigated: this card's copy and HAOO's own
copy can drift and nothing checks that they agree. `productRoute` was withdrawn with a named
successor, using the project's five-element withdrawal shape, because a slug-derived route can only
ever produce the path decision (d) makes a 404.

The separation claim is now artifact-level, not just source-level. `posthog-js` left both manifests,
taking twelve packages and 132 lockfile lines with it; the define block, the vendor chunk seed and
the second build input left `vite.config.ts`; all five build-time declarations left
`src/vite-env.d.ts` in the same commit as their readers. The deployed bundle is 179,584 bytes with
**zero** hits for `posthog`, `us.i.posthog.com`, `haoo_page_view`, `visitOrdinal`, `lastSeenDay`,
`googletagmanager`, `Authorization` or `Bearer `, and the previously deployed
`/assets/posthog-sdk-DE6Cs-ON.js` now returns 404.

Every inventory was narrowed per entry, with no forbidden regex group deleted because its subject
left. Twenty-seven cases were retired, each naming a successor by title in the HAOO repository, and
**all 27 titles were verified reachable there** with `git grep -c -F` before the record was written.

## Decisions Made

**The published HAOO document was deleted, against the plan's step B wording.** Step B says the
document "does not leave: [it] was already moved by plan 04.2-02". It had not left this tree —
`products/haoo/index.html` was still tracked here. It is HAOO source, it exists as the HAOO
repository's root `index.html` (confirmed), and leaving it would have made the plan's own
acceptance criteria unsatisfiable and left dead source no build input reads. Deleting it does not
make 04.2-07 impossible: that plan ships `public/products/haoo/index.html`, a different file copied
verbatim out of `public/`.

**The card's preview points off-site.** Step C says to point it at "this repository's own copy of the
asset, which plan 04.2-07 retains at the retired path". Split contract decision (d) supersedes that:
the four assets are let go and the path 404s. The record points at
`https://www.haoo.online/brochure/brochure-preview.png`, which returns 200. Recorded as D22.

**`MEASUREMENT_PRIVACY_FORBIDDEN` and `MEASUREMENT_FACADE_BOUNDARY` were retired.** The plan
prohibits deleting a boundary group because its subject left, and that prohibition was honoured for
the five groups that still have subjects here — all byte-identical. These two had no possible
subject left at all, and a group that cannot fail is decoration rather than a boundary. Retired with
named successors and an in-file withdrawal block (D14).

**`public/.htaccess` and `public/CNAME.txt` were left in place.** The split contract says to "delete
or annotate both in the ZPH reduction commit", but 04.2-07 task 3 declares both in its own
`files_modified` with its own acceptance criterion, and the owner may prefer annotate over delete.
Deciding here would have pre-empted that plan.
