**Copy, never invent.** Read the three existing repository variables from the ZERO-PAPER HUB
repository and write the same names and values to the HAOO repository. A hand-typed project key would
send this site's events into a project the owner does not control, and the value is not something to
reconstruct from memory or from documentation.

Write them as repository **variables**, never as secrets. The build inlines every browser-prefixed
value into the published bundle, so all three are world-readable the moment the site deploys, and the
project key is public and write-only by design. Storing one as a secret would imply a
confidentiality property the artifact cannot have.

The fourth browser-prefixed name both workflows reference is real, deliberately unset, and resolves
to a working fallback. Do not create it. Record in the summary that three were created while four are
referenced, so the counting correction the split contract records stays visible.

**Delete all three from ZERO-PAPER HUB.** This is the configuration-level half of the separation
claim. The fail-closed provider selector means the reduced build would carry nothing even if a
variable lingered — but that is the safety net, not the proof, and the requirement is a claim about
both sides.

**Redeploy both and confirm the asymmetry — using a discriminator that can actually fail.** Trigger a
run on each repository, then assert the transition.

Do **not** use the vendor analytics chunk as the HAOO-side evidence. The build config's own comment
records that the chunk is a `manualChunks` seed which ships in every build since the SDK was bound in
a value position; it is not gated on the provider, so its presence is green in an unconfigured build
and proves only that the partition seed exists.

The discriminator the build config actually provides is the inlined approved-host array: it resolves
to an empty array unless the provider is deliberately selected, so the ingestion origin appears in the
project bundle if and only if the variables took effect. Fetch the deployed HAOO project bundle,
prove it non-empty, and assert the origin literal is PRESENT — derived from the repository's
approved-host contract module rather than restated. Plan 04.2-02 task 3 asserted the same origin
ABSENT before the variables existed, so the two together are a real before-and-after rather than a
pair of assertions that were always going to pass.

For ZERO-PAPER HUB the chunk check is meaningful in the opposite direction, because the dependency
itself was removed there: assert no vendor chunk and no ingestion origin in a fetched bundle proved
non-empty first.

**Enforce HTTPS on the HAOO site.** Read the certificate state from the Pages API first. If it is
approved, enable enforcement. If it is not yet issued, record the state and the timestamp, retry, and
only if it remains unissued record it as owed with the wall-clock reason — issuance is GitHub-side
and not something the project controls.

If any operation here returns an authentication or permission error, that is an authentication gate
rather than a failure. Surface it as one and continue once credentials are available.
