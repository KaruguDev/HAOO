# Phase 04.2 Plan 04: Make the Disclosure True on a Standalone Domain Summary

**A data-controller statement naming ZERO-PAPER HUB as operator and recipient, enforced as required type members so omission is a build failure, plus a storage-key rename and schema bump that reset the bounded browser context at the new origin with no migration code.**

## Performance

- **Duration:** ~20 min of execution, after a halt at the blocking-human gate
- **Tasks:** 3 (one checkpoint, two implementation)
- **Files modified:** 7 in HAOO, 1 in ZPH planning
- **Suite:** 672 → 674 passing, 10 files, green

## Accomplishments

The disclosure now answers a question it did not answer at `www.haoo.online`: who operates HAOO and who receives the data. On the parent company's hostname the controller was implicit in the address bar; on a standalone domain no sentence on the page said it. The approved copy is rendered as its own labelled region immediately before the processor group, so the disclosure reads controller-then-processor — who has my data, then who handles it for them — with the jurisdiction sentence still attached to the processor where it belongs.

`controllerHeading` and `controllerNote` are **required** members of the disclosure type, not optional ones. That is the substance of the change rather than a detail of it: a product configuration that forgets the controller statement now fails typecheck instead of rendering a blank where a promise about a visitor's data should be.

The bounded browser context resets cleanly at the new origin. The storage key lost the parent-company prefix and the schema version was bumped in the same two-line data edit, with no code change and no migration.

## The rename and the bump

`storageKey: 'zph.haoo.ctx.v1'` → `'haoo.ctx.v2'`, `schemaVersion: 1` → `2`. Two data edits, no code.

These are mechanically different operations and both were wanted. The **rename** does not find the old record at all and leaves it orphaned. The **bump** finds a record under the *new* key carrying the *old* version and **removes** it rather than merely ignoring it — that is the half that makes "handled as a schema-version event" literally true rather than approximately true. The new case asserts both halves, including that the orphan is left byte-identical under the old key (the reader only ever touches the configured key) and that nothing throws on either path.

No migration code was written because there is none to write: browser storage is origin-scoped, so records at the parent origin were already unreachable. No cross-origin handover was built — it is mechanically indistinguishable from the cross-site identity technique this product's own disclosure denies.

## Deviations from Plan

### 1. [Rule 1 — Bug] The version bump would have silently inverted a rejection fixture

- **Found during:** Task 3, while measuring the blast radius before editing.
- **Issue:** `src/test/measurement.test.ts:221` pinned its `'unknown version'` invalid-record fixture to the literal `2`. Bumping `schemaVersion` to `2` would have made that fixture a **valid** record while the case still asserted it was rejected. The case would have failed loudly if lucky, or — worse — silently stopped testing what its name claims.
- **Fix:** derives `SCHEMA_VERSION + 1`. Five further record fixtures in `measurement-page.test.tsx` hard-coded `version: 1` and now derive from `HAOO_MEASUREMENT`, and both suites' `CONTEXT_KEY` now reads `HAOO_MEASUREMENT.storageKey`.
- **Verification:** `npx vitest run src/test/measurement.test.ts -t 'schema'` → 22 passed; full measurement suite 251 → 252.
- **Committed in:** `22e650e`. The plan's own action text directed exactly this ("if any hard-codes either literal, that is a latent bug this rename exposes and it should be fixed here").

### 2. [Rule 3 — Blocking] Task 3's "exactly two files" criterion is unsatisfiable

- **Found during:** measured *before* task 3 ran, while halted at the gate; recorded as **D24**.
- **Issue:** the plan scopes task 3 to two files, but `src/test/measurement-page.test.tsx:28` hand-coded the shipped key and backs eight assertions reading real `localStorage`. The rename cannot land as a two-file diff without leaving the page suite red.
- **Resolution:** **surfaced, not weakened.** The corrected three-file form was used and the realized diff is exactly the three files predicted. The sibling criterion carrying the criterion's real content — no diff under `src/measurement/` — was left untouched and measures `0`.

### 3. [Rule 1 — Bug] A comment I wrote broke a satisfiable criterion

- **Found during:** Task 3 verification. My own explanatory comment in `haoo.ts` contained the literal `zph.`, making `grep -c 'zph\.' src/products/haoo.ts` return `1` instead of `0`.
- **Fix:** reworded the comment. The criterion was satisfiable as written and I had broken it, so the comment was fixed rather than the criterion. The old key is now named in full exactly once in the repository — in the reset case, where it is the thing being proven unreachable.
- **Verification:** `grep -c 'zph\.' src/products/haoo.ts` → `0`.

**Total deviations:** 3 (2 bugs auto-fixed, 1 unsatisfiable criterion surfaced and recorded rather than weakened).
