**Mapped:** 2026-09-05
**Files analyzed:** 76 tracked non-`.planning` files (all classified), of which 8 are genuinely new artifacts and 5 are structural rewrites
**Analogs found:** 8 / 8 new artifacts

## How to read this document

This phase is a **repository split**, not a feature build. Most "new" files in the HAOO repository
are existing files at the same relative path — for those, the analog *is the file itself*, and what
matters is not a pattern to copy but the **set of constraints on the move**: which test inventory
names the path, which import-graph edge must be re-pointed, and whether the path or hostname appears
as a **string literal** in an assertion.

Three sections follow:

1. **§Relocated files** — move constraints, no invented patterns.
2. **§New artifacts** — these DO need analogs; concrete excerpts given.
3. **§Withdrawal pattern** — the project's established "retire with a named successor" shape, which
   D-05 requires verbatim for PROD-06.

## Pattern Assignments — genuinely new artifacts

### 2.1 `public/products/haoo/index.html` (ZPH) — recovery document

**Role:** published document · **Data flow:** request-response (static)
**Analog:** `products/haoo/index.html` — the project's only other hand-authored HTML document that
is *not* a React mount point in the meaningful sense. Match quality: **role-match**.

What the analog establishes, and what the new file must diverge from:

**Head shape to copy** (`products/haoo/index.html:1-9`):
```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <link rel="icon" type="image/png" href="/zero-paper_hub_hi-def.png" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>HAOO Property Management | ZERO-PAPER HUB</title>
    <meta name="description" content="…" />
    <link rel="canonical" href="https://www.zero-paperhub.com/products/haoo/" />
```

**What must NOT be copied.** The analog ends with a mount point and a module script
(`products/haoo/index.html:48-49`):
```html
    <div id="root"></div>
    <script type="module" src="/src/main.tsx"></script>
```
D-12 forbids both. The recovery document has no `#root`, no `<script>`, no form, no measurement.

**Delivery mechanism — the load-bearing difference.** The analog is a `rollupOptions.input` entry
(`vite.config.ts:40`). After the split that input is gone, so the *only* remaining route to
`dist/products/haoo/index.html` is Vite's verbatim `public/` copy. Author at
`public/products/haoo/index.html`; add no build wiring. (RESEARCH Pattern 2.)

**Body:** meta-refresh at `content="0; …"` (an instant refresh is read by Google as permanent; a
delayed one as temporary), `<link rel="canonical" href="https://haoo.online/">`, and one visible
anchor. `robots` directive is a deliberate judgement call, not a copy.

**Note the ZPH `noscript` precedent** (`products/haoo/index.html:23-47`): this project consistently
ships a working no-JavaScript path. The recovery document's visible link is that same discipline —
the meta refresh is the enhancement, the anchor is the guarantee.

### 2.3 `scripts/verify-tree-disjointness.mjs` + `shared-scaffold.txt` — the SPLT-01 check

**Role:** CLI utility · **Data flow:** batch
**Analog:** `scripts/verify-phase4-coverage.mjs`. Match quality: **exact** (same role: a
version-controlled auditor wired into CI that reads a file and throws with an enumerated error list).

**CLI shape to copy** (`scripts/verify-phase4-coverage.mjs:300-317`):
```js
async function main() {
  const coveragePath = process.argv[2];
  if (!coveragePath) {
    throw new Error('Usage: node scripts/verify-phase4-coverage.mjs .planning/phases/04.1-…/COVERAGE.md');
  }

  const result = auditPhase4Coverage(await readFile(coveragePath, 'utf8'));
  console.log(
    `Phase 4 coverage audit passed: ${result.requiredRows} required capabilities across ${result.tables} tables.`,
  );
}

if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
  main().catch((error) => {
    console.error(error instanceof Error ? error.message : error);
    process.exitCode = 1;
  });
}
```
Copy all four properties: **path as `process.argv[2]`** (this is exactly what makes the verifier
relocatable — it is why `verify:coverage` moves cleanly), the **usage error**, the
`import.meta.url === pathToFileURL(process.argv[1]).href` guard so the module stays importable by a
test, and `process.exitCode = 1` rather than `process.exit`.

**Failure-reporting shape** (`scripts/verify-phase4-coverage.mjs:290-292`):
```js
  if (errors.length > 0) {
    throw new Error(`Phase 4 coverage audit failed:\n- ${errors.join('\n- ')}`);
  }
```
Accumulate every offending path and report them all in one run — do not fail on the first.

**Success-line shape** (`:306-308`): print the *count* of what was checked, not just "passed". A
disjointness check should print how many paths were compared and how many allowlist entries were
subtracted, so a run that compared nothing cannot read as green.

**Non-empty guard — the pattern this project applies everywhere.** `build-output.test.ts:1641-1642`:
```ts
      const probeProjectBundle = projectBundleText(probeDir);
      expect(probeProjectBundle.length).toBeGreaterThan(0);
```
with the comment *"a probe that emitted nothing cannot pass this case by scanning the empty
string."* The disjointness check has the identical failure mode: `comm -12` over two empty
`ls-files` outputs prints nothing and reads as success. Assert both file lists are non-empty first.

**The check itself** (RESEARCH §"Verifying the two trees are disjoint"):
```bash
comm -12 <(git -C zero-paperhub ls-files | sort) <(git -C haoo ls-files | sort) \
  | grep -v -x -F -f shared-scaffold.txt
# → must print nothing
```
plus the two positive halves (ZPH grep for `haoo` outside `*.md`/lockfile → only `registry.ts` +
`public/products/haoo/index.html`; HAOO grep for `HomePage|downloadCompanyProfile|NAV_LINKS` under
`src/` → nothing).

**`shared-scaffold.txt`** is a plain newline-delimited allowlist of the 19 paths in §3 above.
Analog for the *doc-comment discipline*: `src/test/focus-contrast.test.ts:27-33` — a closed list
whose comment states why it is closed and how it is extended:
> *"Phase 1 established the list; Phase 2 keeps it closed by registering each new interactive
> component here rather than by widening RING_COLOR_TOKENS, so a focus style that is never measured
> cannot ship."*

Write the equivalent sentence for the scaffold list: entries are added by declaring toolchain
ownership, never by adding a file the other half also needs.

## Shared Patterns

### Withdraw with a named successor (D-05's required shape)

**Sources — three real examples, in increasing formality.**

**(a) The canonical in-code example** — `src/measurement/posthog.ts:91-108`, on the assertion/constant
itself, not in a changelog:
```ts
  /**
   * WITHDRAWN by plan `04.1-09`. Successor: `unusableBoundClient`.
   *
   * This named the refusal for an empty provider slot, on the premise that an absent
   * client meant an unconfigured page and that this module installed no stub of its own.
   * Since `04.1-09` bound the pinned SDK in a value position, an EMPTY slot is the normal
   * path rather than a refusal: `resolveClient` falls back to `boundPostHogClient()` and
   * proceeds. The gate it used to guard did not disappear — it moved to the bound value,
   * which is checked for a callable initializer on exactly the terms an ambient value is,
   * and refuses as `unusableBoundClient` when it has none.
   *
   * Retained rather than deleted, and its string value deliberately NOT repurposed. A
   * reader who finds `posthog:absent-provider-client` in an old console record, a report,
   * or a prior summary must be able to see a changed refusal vocabulary rather than
   * mistake it for a refusal path that was silently dropped (D-05, T-04.1-08). Nothing
   * returns it any more; the successor below is what a live build can emit.
   */
  absentClient: 'posthog:absent-provider-client',
```
