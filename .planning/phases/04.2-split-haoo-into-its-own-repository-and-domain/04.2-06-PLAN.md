<objective>
Reduce the ZERO-PAPER HUB repository to itself.

This is the mirror of the tracer, and it has the same atomicity property for the same reason: the
per-file boundary map's non-empty source guard goes red the instant a mapped source leaves the tree,
and sixteen of its eighteen keys leave here. So do the product type module the Products card's
component and test both import, the ambient build-variable declarations whose readers depend on
them, and the vendor chunk seed whose partition case asserts a non-empty vendor side. Every one of
those is a case that fails at an intermediate step. There are no intermediate steps.

What survives is a company site with a Products section, and one product card that links out.

Purpose: the artifact-level half of the separation claim — not "the sources are gone" but "the
thing that ships carries none of it".
Output: a reduced repository that builds green and ships no measurement.
</objective>

**Step A — confirm before deleting.** For every path about to be removed, confirm it exists in the
HAOO repository at the expected location. A deletion made before the other side is pushed is
unrecoverable except from history, and while D-02's ordinary deleting commit does keep it in history,
the check costs nothing and the alternative is a bad afternoon.

**Step B — delete the HAOO half (D-02, ordinary `git rm`, never a rewrite).** The product page
component; the seven shell files under the components directory; the product copy, engagement-summary,
types and definition modules under the products directory; the three measurement modules; the six
reporting modules; the approved-ingestion-host configuration module; the report generator script and
the capability-coverage verifier script; the four HAOO assets under the public products directory;
and the ten HAOO test files and two test fixtures. The product page's own published document and the
Products section component do **not** leave: the first was already moved by plan 04.2-02, and the
second is this repository's.

**Step C — sever the build-time coupling with an inline card record (D-06).** The registry module
today imports the HAOO product definition and the product type. Both are gone. Rewrite it to hold
the card's facts inline, with a type declared locally in the same file.

Preserve the three exported names the Products component and its test consume — the section anchor
identifier, the navigation label and the collection — because those names are the contract between
the registry and its consumers, and renaming them would turn a data change into a refactor. Preserve
the presence-derived navigation function unchanged: a card record is still "a product is live", so
its behaviour is unaffected.

The route function is the one that must change. It derives a same-origin path from a slug, and under
D-06 the card carries an absolute link to the HAOO domain instead. Either give the record a link
field and retire the route function with a named successor, or have it return the record's link
directly — Claude's discretion, but if it is retired, retire it with the project's five-element
withdrawal shape rather than deleting it.

The record's fields are read off what the Products component actually renders, sourced from the HAOO
product definition before it leaves: the product name, the parent-relationship line, the outcome
line, the audience lead sentence, and the nested brochure object carrying the preview image href,
alt text, width and height. Keep the brochure object nested — the component destructures it, and
flattening it would be a component change bought for nothing. Point the record's preview image at
this repository's own copy of the asset, which plan 04.2-07 retains at the retired path; note in the
record's doc comment that the asset is deliberately duplicated and why.

Write D-06's accepted cost into the record's doc comment, named rather than mitigated: this card's
copy and HAOO's own copy can drift, and nothing checks that they agree. That is the price of having
no build-time dependency on the other repository, and it was paid deliberately.

**Step D — re-point the two consumers, and the root component.** The Products component's import of
the product type becomes an import of the locally declared card type; nothing else about it changes.
The Products section test imports the home page component, the HAOO product definition and the
product type; the second and third are gone, so it must build its fixtures from the card record's
own shape. Preserve every one of its thirteen cases and its red marker — this is a re-pointing, not
a rewrite, and a case lost here is a case lost from the Products contract Phase 1 established.

In the root component, delete the branch on the document dataset attribute along with the product
page import, the product definition import and the product type import. The default export becomes
the home page directly. Do not shrink the branch — remove it; after the split this repository has
exactly one document and a branch that can never take its other arm is the anti-pattern the refreshed
architecture map names.

**Step E — reduce the build, the dependency tree and the ambient declarations, together.** These
three are one change because each is load-bearing for the others' assertions.
  - The build config keeps one input, the site root document. Delete the second input, the
    configuration-module import, the whole define block and the vendor chunk seed list. The comment
    above the define block explains a contract this repository no longer has; remove it with the
    block rather than leaving a paragraph describing machinery that is not there.
  - Remove the analytics SDK from the dependency manifest and reinstall from the lockfile so the two
    agree. This is not tidiness: the separation claim is about the artifact, the SDK is imported in a
    value position by a module that is leaving, and leaving the dependency behind leaves the door
    open for the next contributor.
  - Delete the four build-variable declarations and the ingestion-host declaration from the ambient
    declaration file, in this same commit as their readers. The bidirectional exhaustiveness
    invariant is the point: one case asserts every declared variable is read by production source,
    the other asserts every read variable is declared, and a declaration outliving its reader fails
    the first. The recorded precedent for exactly this bidirectional move is in the phase's
    deferred-items record. Keep the file's own rule intact — it may contain no import and no export,
    or it stops augmenting the global environment shape.
