## Decisions Made

- **The allowlist was not widened.** Four of the seven shared paths are textbook entries under the
  list's own rule; adding them would have made the run pass. The list's header forbids exactly that,
  and the list is a decision recorded in the contract, so the disposition is the owner's.
- **Checkout identity is read from `CNAME`, not from argument order.** `CNAME` is on the allowlist as
  a path and holds a different hostname on each side, which makes it the one file that can tell the
  trees apart. This also refuses the same checkout passed twice — the `cd ""` hazard
  `04.2-split-env.sh` exists to prevent, in the auditor rather than only in the shell.
- **The guard moved onto the post-exclusion lists.** See Deviations.
- **Not wired into CI, deliberately** (D30). The check needs two checkouts and a runner has one. The
  half that needs only one tree — the pinning case — runs in CI in both repositories on every push.

### Decision 1 — the shared-path half: ratify all seven, 19 → 26, on two grounds

`shared-scaffold.txt` is now **26 entries in both repositories, `cmp` clean**, carrying a one-clause
reason per entry and marking the two grounds with machine-readable `# @ground:` directives.

- **Ground A (23) — shared toolchain scaffolding.** The original nineteen plus `index.html`,
  `scripts/assert-phase1-red.mjs`, `shared-scaffold.txt` and `scripts/verify-tree-disjointness.mjs`.
  All four qualify under the list's rule exactly as it already stood.
- **Ground B (3) — ratified path collisions with divergent content.** `src/App.tsx` and the two
  suites. Same path, entirely different content, so neither tree contains the other's source.

**Ground B's decay is checked, not commented.** A path allowlist forgives a Ground B entry whether or
not its copies have converged — and a converged copy is a genuine SPLT-01 violation. So the auditor
asserts per entry that the two copies are **not byte-identical** and reports convergence, with the
message explicitly forbidding the obvious wrong fix (moving the entry to Ground A). Demonstrated by
copying HAOO's `src/App.tsx` over the ZPH copy:

```

  allowlisted on the ground that its two copies hold different content, and that ground no longer
  holds. Do not move it to the scaffold ground; that would declare a genuine violation to be
  scaffolding.
```

Reverted → green.

### Decision 2 — the positive half: narrow the subject to product source

The assertion is now that the ZERO-PAPER HUB tree **ships no HAOO product source**, not that no file
may name the product. The **subject** was narrowed; the **threshold** was not relaxed.

**The exempt class is structural, never a skip list.** No path in the auditor enumerates the eleven
files that were failing — an exemption naming today's offenders is exactly the stale, vacuous pass
this plan refused earlier. Product source is: a file under `src/` or `public/`, or a root-level
`*.html`, that is not one of the two named carriers, not a test, not an ambient declaration and not
documentation. Tooling (`scripts/`), CI (`.github/`), the manifests, the tool configs and the
lockfile fall outside that class **by construction**, without being listed.

Probes run over **comment-stripped** content — a comment recording that the product LEFT is not
product source, and the tree carries those deliberately so a reader finds a recorded reduction rather
than an unexplained absence. The URL form `https://www.haoo.online/` survives stripping and still
counts.

**A second probe was added because the first was measurably insufficient.** The initial injection
demonstration used `src/components/BrochurePanel.tsx` and the check **passed** — that file contains
**zero** occurrences of the product name, being parameterised by `productName`. A name-only probe
would have admitted genuine HAOO product source. So `HAOO_PRODUCT_SYMBOLS` was added, the mirror of
the `HOME_PAGE_SYMBOLS` list already asserted on the HAOO side: thirteen symbols, each measured
**absent** from ZPH product source and **present** across HAOO's `src/`, so each discriminates rather
than decorates. The residual limit — a HAOO file that neither names the product nor uses a registered
symbol is product-agnostic by construction and fails `npm run typecheck` on unresolvable imports — is
stated in the source rather than hidden.

The two **named carriers** are exempt from the leak assertion and separately asserted to **still**
name the product, so a vanished card or recovery document is a finding rather than a cleaner tree.
