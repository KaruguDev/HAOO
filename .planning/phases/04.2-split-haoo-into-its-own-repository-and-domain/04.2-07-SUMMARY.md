## Accomplishments

**The retired path has a real answer, and it is the only honest one this host allows.** GitHub Pages
emits no per-path 3xx and supports no user server configuration, so `public/products/haoo/index.html`
is a documented last resort rather than a preference — and the document says so, in a comment, naming
the three mechanisms (a rewrite-engine config, a host redirects file, a generator front-matter key)
that are real elsewhere and silently do nothing here. It carries a zero-second refresh, because
Google reads an instant refresh as a permanent move and a delayed one as temporary; a byte-identical
`rel="canonical"`, because the search guidance treats the two as different jobs; `robots:
noindex, follow`, with its reasoning recorded beside it; and two visible anchors, because the refresh
is the enhancement and the link is the guarantee.

**No build wiring was added, and none was needed.** `vite.config.ts` names one input and it is not
this path, so verbatim copying of `public/` is the whole mechanism — which is exactly why the new
case reads `dist/products/haoo/index.html` rather than the source. A copy that never happened would
satisfy every source-level check and fail the visitor.

**The separation claim moved from inference to evidence.** Until now SPLT-03's support in this
repository was the *absence* of the modules, the dependency and the configuration — three source-level
facts from which a measurement-free build is inferred. The new artifact case observes it: it proves
the bundle non-empty first, then asserts five labelled absences over what the browser actually
receives. Deleting `dist/assets` makes the case fail rather than pass, demonstrated and restored.

**Two files that lied about the mechanism are gone.** `public/.htaccess` carried a `mod_rewrite`
catch-all to `/index.html`; a reader asking the exact question this plan answers would have found it
and concluded there is a rewrite. There is not. The path resolves because a physical file exists
there. `public/CNAME.txt` was an unread 21-byte duplicate of the real `CNAME`, and a second copy of
one half of a two-repository domain pair is a place for a drift nothing would catch.

## Decisions Made

**Zero scripts, asserted as an exact number.** Plan 04.2-04 task 1 offered the owner Option C — have
this document clear the orphaned browser record at the retired origin — and it was rejected (D25).
The case asserts `toHaveLength(0)` on `<script` matches, not a maximum, because a range would accept
both dispositions and the point of a recorded decision is that only one of them is correct here.

**`robots: noindex, follow`.** A judgement call, and the alternatives are named in the document's own
comment. Indexing would publish a content-free page under a retired path competing with the page it
points at; `nofollow` would strand the consolidation signal on a page nothing may index. `noindex,
follow` keeps the canonical and the anchor working while keeping the stub out of the index.

**A second anchor, to the brochure.** The plan's criterion is "exactly one anchor element whose href
is the HAOO page URL", and there is exactly one. The second anchor points at
`https://www.haoo.online/brochure/HAOO-Marketing-Brochure.pdf`, which the split contract requires
("the stub's links must point at the new root-level `www.haoo.online` asset URLs, never at the dead
ZPH paths") and which D22 restates. The case asserts that *every* anchor href is on the HAOO host, so
a dead ZPH asset path cannot be linked from here.

**Delete, not annotate.** The plan offered either for the two inert files. Deletion was chosen: a
file whose only remaining content is a comment saying it does nothing still turns up in a grep, and
the reader still has to work out that it is inert.
