# Phase 04.2 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Seeded from `04.2-RESEARCH.md` §Validation Architecture.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 3.2.4, jsdom 26.1.0, `@testing-library/react` 16.3.2 |
| **Config file** | `vitest.config.ts` — `environment: 'jsdom'`, `globals: false`, `setupFiles: ['./src/test/setup.ts']` |
| **Quick run command** | `npx vitest run src/test/<file> -t '<case>'` |
| **Full suite command** | `npm test` (= `npm run build && vitest run`) |
| **Estimated runtime** | ~60-90 seconds (build-first) |

> **`npm test`, never `npm run test:unit`** — RESEARCH Pitfall 9. `test:unit` skips the build,
> so every `dist/`-reading assertion in `build-output.test.ts` validates a STALE artifact and can
> pass on a tree that does not build. This phase changes both Vite inputs and both workflows, so a
> stale-artifact pass is a live risk, not a theoretical one.

**Two repositories.** Every command below runs in EACH repository the wave touched. A wave that
edits only one repository runs only that one; a wave that edits both must be green in both before
it merges.

---

## Sampling Rate

- **After every task commit:** `npm run typecheck && npm run lint && npx vitest run <touched suite>`
- **After every plan wave:** `npm test` (build-first) in every repository the wave touched
- **Before `/gsd-verify-work`:** `npm test` green in BOTH repositories, `npm run verify:coverage`
  green in the HAOO repository, both Pages deploys green
- **Max feedback latency:** ~90 seconds
