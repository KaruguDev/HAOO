<objective>
Give the retired path a real answer, and prove the reduced artifact is actually reduced.

This host emits no per-path redirect and supports no user server configuration, so the only honest
answer available is a published document that carries the visitor across by an instant refresh, tells
a crawler the HAOO page is canonical, and — because this project consistently ships a working
no-JavaScript path — offers a visible link that works when neither of those does. That is a
documented last resort, and naming it as one in the amended requirement is part of shipping it
honestly.

The second half is the artifact-level claim. Removing the sources and the dependency makes the
reduced build measurement-free; only a scan of the built output proves it. And a scan that proves
nothing is worse than no scan, so it must first prove it had something to scan.

Purpose: a bookmarked link still works, and the separation claim is evidence rather than inference.
Output: a scriptless recovery document, four retained assets, and two new cases.
</objective>

**Author the document under the public directory, at the retired path, and add no build wiring.**
With the HAOO build input removed in plan 04.2-06, verbatim copying of the public directory is the
only remaining route to a file at that path. That is the whole mechanism; a build input would be a
second, redundant one.

**What the document contains.** A minimal head: doctype, character set, viewport, a title saying
HAOO has moved, and — the three load-bearing elements — an instant meta refresh pointing at the HAOO
page, a canonical link pointing at the same page, and a robots directive. Use a zero-second refresh:
an instant refresh is read by search as a permanent move, while a delayed one is read as temporary,
which is the opposite of what a site move wants. The canonical is complementary rather than a
substitute — the search guidance treats redirects and canonicals as different jobs, and this document
ships both deliberately. The robots directive is a judgement call rather than a copy: prefer
excluding the retired URL from the index while still following its links, so the canonical carries
the signal, and record the choice with its reasoning in a comment.

A body with one sentence and one visible anchor to the HAOO page. This is not decoration. The
refresh is the enhancement; the anchor is the guarantee, and it is the same discipline every
`noscript` block in this project follows.

**What it must not contain.** No mount point, no module script, no form, no measurement, no product
content. It is a static document, not a route (D-12). The one exception is conditional: if plan
04.2-04's owner answer was to clear the orphaned browser record, add exactly that removal in a
try-catch and nothing else, and say in a comment that it is cleanup rather than measurement and that
it is the entire script budget of this file. If the answer was to accept the orphan, the document
carries no script at all and the comment records that the question was asked and answered.

**Do not reach for a redirect mechanism this host does not have.** A rewrite configuration file, a
redirects file and a static-site-generator front-matter redirect key are all real mechanisms on other
hosts and all do nothing here. The last of those emits the same meta-refresh document this task is
authoring, plus a build this repository does not run.

**Place the retained assets.** Per the split contract's recorded disposition, copy the four HAOO
assets into this repository's public products directory at the identical relative path, so a
bookmarked URL differs from its HAOO equivalent only by hostname. **Copy the bytes; never
regenerate.** Two of the four are pinned by SHA-256 in the suite precisely so the move can be proved
intact — a regenerated preview image with the same visual content is a different file and would
falsify the pin. Verify both hashes after copying, before committing.

Note in the summary that the preview image is now present in both repositories: the HAOO page renders
it and this repository's Products card renders it too. That duplication was recorded in the split
contract's shared-scaffold reasoning; plan 04.2-08's disjointness check must not read it as a
violation.
