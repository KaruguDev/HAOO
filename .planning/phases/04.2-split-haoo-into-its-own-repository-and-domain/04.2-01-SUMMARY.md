## Decisions Made

The four structural choices were the owner's (task 2), recorded verbatim into the contract. Two were **not** the planner's defaults and their fan-out is the main thing later plans must absorb:

- **(b) Assets MOVE to a root-level directory.** The default kept them at `public/products/haoo/` specifically so `PRODUCT_ASSETS`, the `alternate` href, the five `noscript` hrefs, `pdfHref`, `previewImageHref` and `downloadName` stayed byte-unchanged. Every one of those is now an edit, and both SHA-256 pins move with their path constants. Plans 04.2-02 and 04.2-03 own this; the contract tabulates each literal with its file and line.
- **(d) Retired ZPH asset URLs 404.** No copies, therefore no retention period — so the amended PROD-02 states the 404 disposition instead of citing Google's site-move guidance, and `shared-scaffold.txt` needs no asset exception. This does **not** repeal D-12: the meta-refresh recovery document for the retired *page* still ships in plan 04.2-07, with its links pointed at the new root-level `haoo.online` asset URLs.

Two execution-level decisions were mine:

- **Flagged `assets/` rather than recording it silently or refusing to record it.** The orchestrator specified the value with the owner's amendment window explicitly open. Recording it silently would have set plans 02/03 up to trip; refusing to record it would have left every literal in the contract unresolvable. Recording it *with* the measurement and a recommended amendment surfaced the collision to the owner, **who then settled Q3 as `brochure/` the same day** — the contract now carries `brochure/` throughout, and the `assets/` collision reasoning is retained as a standing prohibition because it governs any future asset move in either repository.
- **The disjointness check inside `## Shared scaffold` is an indented block, not a fenced one.** The section's extraction takes fenced content and plan 04.2-08 copies that extraction verbatim into `shared-scaffold.txt`; a second fence would have written `comm -12 …` into the allowlist as if it were a path.

**1. [Rule 2 - Missing Critical] Recorded asset directory collides with Vite's build output directory**

- **Found during:** Task 3, while writing `## Published document path`
- **Issue:** The directory to record was `assets/`, which is Vite's default `build.assetsDir`. `dist/assets/` already holds `main-*.js`, `main-*.css` and `posthog-sdk-*.js` `[MEASURED: ls dist/assets]`, and `src/test/build-output.test.ts:294-298` builds `BUILD_OUTPUTS` from **every** file under `dist/assets` — unfiltered, not just `.js` — then `readFileSync`-scans each against the credential-shape regexes at `:285-293`. Moving the four product assets there would feed a 2.3 MB PDF and three PNGs into that scan as text. Filenames do not collide (bundles are content-hashed) so the build still succeeds, which is what makes this the kind of defect that surfaces two plans later as a confusing test failure rather than immediately.
- **Fix:** Recorded `assets/` as instructed — the value was specified with the owner's amendment window explicitly still open — and added a blocking flag in `## Published document path` carrying the measurement, plus carried-forward question **Q3** naming the owner and the moment it is due. Not silently substituted: the directory is a one-way choice once URLs are published and indexed, which makes it the owner's to make. **The owner settled it the same day: `brochure/`.** The contract was then amended so every literal resolves against `brochure/`, Q3 was closed as RESOLVED, and the `assets/` collision reasoning was kept in place as a standing prohibition on that directory.
