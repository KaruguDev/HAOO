# Phase 04.2 Learnings: Split HAOO into its Own Repository and Domain

## Decisions

### Split by full clone plus an ordinary deleting commit — never a history rewrite
HAOO was seeded by cloning ZERO-PAPERHUB and pruning the non-HAOO half, keeping all 412 commits.
HAOO source left ZERO-PAPERHUB by a normal deleting commit; past commits still carry the files.

**Rationale:** `git blame` and `git log --follow` keep working on every HAOO file, so the rationale
encoded across Phases 1–04.1 stays reachable from the code it constrains. `filter-repo` would have
force-pushed over every existing clone and broken the commit SHAs that `.planning/` cites directly.
Accepted cost: HAOO's history contains commits touching nothing in its tree, and ~32MB of `.git`.
**Source:** 04.2-CONTEXT.md (D-01, D-02), 04.2-01-SUMMARY.md

### The canonical domain leg was reversed AFTER the apex had shipped, and the reversal was kept visible
`www.haoo.online` is canonical; the apex 301-redirects to it. This reversed the owner's own
2026-09-05 answer, *after* plan 04.2-02 had already shipped the apex and proved it live.

**Rationale:** A reversal recorded only as its outcome would read as though `www` was always the
choice, making `04.2-02-SUMMARY.md` look wrong rather than superseded. The mechanism is mirror-imaged,
not replaced — the same single `CNAME` line decides the leg, and Pages supplies the counterpart
redirect either way.
**Source:** 04.2-SPLIT-CONTRACT.md § Domain → Decision (a) reversal

### PROD-06's reuse-across-products half is withdrawn with three named successors, not deleted
After the split HAOO holds exactly one product, so "demonstrates reuse across more than one product"
became unprovable there and cannot be restored without a second product.

**Rationale:** Withdrawing with named, reachable successors keeps the ID and records what stopped
being provable and why. Verification confirmed all three successors present by exact title and green —
and the first (a synthetic `ZENITH` product) reconstructs the withdrawn claim's substance without a
registry, so the retirement ended up stronger than what it replaced.
**Source:** 04.2-01-SUMMARY.md, 04.2-DEFERRED-ITEMS.md D5, 04.2-VERIFICATION.md

### The four retired brochure asset URLs are let go; only the retired PAGE keeps a recovery document
The four assets under `https://www.zero-paperhub.com/products/haoo/` 404 after cutover. Nothing was
copied into the ZPH tree and no retention period is claimed.

**Rationale:** A static host emits no per-path redirect, so an already-published asset URL either
resolves or 404s. Decision (d) does not repeal D-12 — the meta-refresh recovery document for the
retired *page* still ships; only the asset *files* are dropped.
**Source:** 04.2-01-SUMMARY.md, REQUIREMENTS.md QUAL-04

### The recovery document ships ZERO scripts, asserted as an exact number
Not "at most one" — exactly zero, bound to D25's recorded rejection of Option C.

**Rationale:** A range would have accepted both dispositions when the decision was that only one is
correct. Verified live: 4,353 bytes, 0 `<script>` tags, carrying a meta refresh, a canonical, and two
plain anchors.
**Source:** 04.2-07-SUMMARY.md, 04.2-UAT.md test 2

### Owner copy approval covers visitor-facing wording ONLY, and does not close the DPA sign-off
SPLT-04 is Complete on the truth of the visitor-facing statements. The Kenya Data Protection Act 2019
sign-off (`02-VALIDATION.md:91`) stays OPEN.

**Rationale:** In the owner's own words at 04.2-04's gate: *"Approving copy is not a data-protection
review."* Different claims; neither implies the other. Recorded in three independent places plus a
disclaimer inside the SPLT-04 Complete row itself, so no later reader can infer closure.
**Source:** 04.2-04-SUMMARY.md (D26), 04.2-09-SUMMARY.md, REQUIREMENTS.md:249

### The disjointness auditor is deliberately absent from both deploy workflows
`verify:disjoint` needs two checkouts; a CI runner has one.

**Rationale:** Better to state why a check cannot run in CI than to ship a CI step that silently
passes on a single checkout.
**Source:** 04.2-08-SUMMARY.md

### The shared-scaffold allowlist was ratified at 26 entries on two distinct recorded grounds
23 shared toolchain files, 3 divergent-content path collisions — each entry carrying its own ground.

**Rationale:** The check was built literal-first and shipped RED with all 18 findings named, so the
owner decided against measured evidence rather than against prose. The corrections followed the
decision; they did not anticipate it.
**Source:** 04.2-08-SUMMARY.md

### Accept the content-blocker undercount now; reopen the CDN decision only on a conversion-RATE trigger
Option A (read every figure as a floor) adopted. Option B (first-party reverse proxy through a CDN)
deliberately declined for now.

**Rationale:** Four recorded reasons: it reopens D-12 at a named cost; it is an arms race, not a fix;
it buys infrastructure ahead of the problem; and it sits in tension with HAOO's measurement posture —
a blocker is a preference the visitor expressed deliberately, so if B is ever adopted the disclosure
must say ingestion is served from this domain. Doing it silently is the one version of B that
contradicts how HAOO measures.
**Source:** 04.2-DEFERRED-ITEMS.md D41

### An absent query echo is accepted as provenance with `confirmed: false`
`validateEchoedQuery` withdrawn; `resolveQueryProvenance` named as successor. Byte-exact equality is
retained for when an echo IS present; only `null`/`undefined` widen.

**Rationale:** PostHog returns `query: null`, so the old behaviour made the owner report unable to run
at all. The widening is exactly as wide as the measurement that forced it — a numeric, boolean or
array echo still refuses. `hogql` still cannot stand in: it is a rewrite, not a restatement.
**Source:** 04.2-UAT.md gap G-04.2-9, HAOO commit 5dfffe8

## Lessons

### A medium-confidence research assumption is only settled by the first LIVE run
`query-provenance.ts` flagged research assumption A4 as medium confidence and wrote, in its own
comment, that "the first live run settles the question loudly instead of parsing to zeros." That run
happened during UAT and settled it FALSE: PostHog returns `query: null`.

**Context:** Every automated test passed throughout, because they all ran against fixtures shaped by
the same assumption. Nothing short of a real API call could have caught it. The code was right to
flag itself, and the flag is what made the failure legible instead of mysterious.
**Source:** 04.2-UAT.md gap G-04.2-9

### A recorded number cannot be a precondition for a later destructive action
D37 scheduled deleting ZPH `.planning/` and cited a 239-file superset walk as THE precondition. Its
trigger was verify-work sign-off — the exact event that writes new ZPH-only planning files.

**Context:** Re-measured right after sign-off: 243 files, 3 ZPH-only. Executed as written, the
`rm -rf` would have deleted the UAT record, the coverage matrix and the verification report. Fixed
structurally rather than by refreshing the number, because a refreshed number goes stale the same way
on the next artifact written.
**Source:** 04.2-VERIFICATION.md finding W-1, ZPH commit 5dfe9b4

### An error message that names the wrong causes costs more than a vague one
The report's failure text said "Check the API key and network connection." Both were fine. It took
four diagnostic rounds to get past a sentence pointing confidently in two wrong directions.

**Context:** The design deliberately collapses every failure reason into one sentence. That protects
the credential boundary but makes an HTTP failure indistinguishable from a validation refusal. The
collapse is defensible; naming specific innocent causes inside it is not.
**Source:** 04.2-UAT.md gap G-04.2-9 artifacts

### Zero is not evidence of nothing happening — it is also what blocked telemetry looks like
Three all-zero report runs looked like a broken ingestion path. The real cause was three independent
content blockers on the owner's own machine: Adblock Plus, a browser-extension VPN, and Vivaldi's
built-in tracker blocking — the last surviving both extension-disabling and private windows.

**Context:** DevTools showed the SDK chunk loading and INITIATING the requests before they were
blocked, which proved `init` succeeded, the lockdown readback confirmed, and `capture` was called.
The Network tab was the discriminator; the Console was not.
**Source:** 04.2-VERIFICATION.md, 04.2-DEFERRED-ITEMS.md D41

### A byte-identical file in two repositories needs both copies corrected in the same change
The 04.1 COVERAGE.md is byte-identical across both repos by design. Two of its Query API rows were
falsified by live measurement.

**Context:** Correcting one side only would have broken the invariant that
`verify-tree-disjointness.mjs` documents. The auditor's pinned row titles also had to be narrowed in
the same commit, 69 → 70 capabilities — the check refused the edit until they were.
**Source:** ZPH commit 3b08e3d, HAOO commit 5dfffe8

### A pinned inventory is what makes a documentation edit safe
Editing COVERAGE.md broke `verify:coverage`, which pins each required capability row by exact title.

**Context:** The failure was the gate working. It forced the row split (one INTEGRATE, one OPT-OUT)
to be a deliberate inventory change rather than a silent prose edit.
**Source:** ZPH commit 3b08e3d

### An amended requirement can disclose a genuine weakening and still be honest
PROD-02's amendment names the mechanism as a client-side meta refresh rather than a 301, and records
that the CDN alternative was considered and scoped out.

**Context:** The guarantee IS weaker than a 301. What makes the amendment sound is that it says so in
its own text rather than preserving the original wording over a weaker mechanism. Verification
checked all four amendments for covert weakening and found none.
**Source:** REQUIREMENTS.md PROD-02, 04.2-UAT.md test 6

### Unsatisfiable acceptance criteria should be recorded as unsatisfiable, not worked around
Across plans 04.2-06, -07, -08 and -09, fifteen acceptance criteria were unsatisfiable as written.
None was made to pass by weakening it or by restoring a deleted asset.

**Context:** Each was recorded with its measured evidence in the deferred-items ledger. The
alternative — quietly satisfying a criterion by changing what it means — is the failure the whole
withdrawal discipline exists to prevent.
**Source:** 04.2-06-SUMMARY.md, 04.2-07-SUMMARY.md (D28), 04.2-08-SUMMARY.md, 04.2-09-SUMMARY.md

### Test with content blockers disabled, or risk recording a false negative
This phase came one step from concluding "ingestion is broken" when the truth was "this browser
blocked it."

**Context:** Now a standing consequence in D41: UAT and any live-measurement check must run with
content blockers and VPN disabled for the site under test.
**Source:** 04.2-DEFERRED-ITEMS.md D41

## Patterns

### Withdraw with a named, reachable successor
Removed code, test cases, requirements and sentences get a withdrawal comment naming a successor whose
existence is verified — and the old name is deliberately not reused.

**When to use:** Any removal where a later reader might otherwise assume a rename. Verified in this
phase by grepping every retired case title in the other checkout before writing the record.
**Source:** 04.2-01-SUMMARY.md, 04.2-02-SUMMARY.md, 04.2-06-SUMMARY.md

### Prove the subject is non-empty before asserting an absence
A scan over an empty set satisfies every `not.toContain`. Guard subject presence first; when the set
is legitimately empty, assert the emptiness EXPLICITLY rather than iterating nothing.

**When to use:** Every absence assertion over a discovered set — bundles, file lists, config rosters.
**Source:** 04.2-06-SUMMARY.md, 04.2-07-SUMMARY.md

### Pair an asserted-empty roster with a mutation probe
An empty roster and a parser that has stopped matching the file look identical. The probe is what
distinguishes them.

**When to use:** Whenever a test asserts that a set is empty rather than that it contains something.
**Source:** 04.2-06-SUMMARY.md

### Assert the built artifact, not the source
Withdrawn text is deliberately retained inside its withdrawal comment, so a source grep finds it and
proves nothing. Read rendered output or the emitted bundle instead.

**When to use:** Any check about what shipped, and every assertion that some text is GONE.
**Source:** 04.2-05-SUMMARY.md, 04.2-07-SUMMARY.md

### Author the expected string a second time, independently
Restate owner-approved copy in the suite as its own constant rather than importing it, so drift in
either copy fails instead of agreeing with itself.

**When to use:** Visitor-facing copy and any string with an external approver. Proved itself in this
session: changing the report caveat failed three tests until the independent copy was updated too.
**Source:** 04.2-05-SUMMARY.md, 04.2-04-SUMMARY.md

### Measure the discriminator, not the concatenation
A bundle check that greps every asset at once passes on the vendor chunk's own default and cannot
fail. Partition first, then scan the chunk that carries the claim.

**When to use:** Any assertion about a built bundle containing or lacking a vendor string.
**Source:** 04.2-09-SUMMARY.md, 04.2-07-SUMMARY.md

### Absent-then-present on the same artifact is the evidence
Either half alone is an assertion that was always going to pass.

**When to use:** Proving a configuration change actually took effect — measure the same artifact
position before and after.
**Source:** 04.2-09-SUMMARY.md

### A one-directional sync asserts by CONTENT after the copy
File identity alone passes on a sync that copied a reverted file. Walk both directions and compare
contents.

**When to use:** Any mirror between two repositories. Used four times this phase; caught nothing only
because it was run every time.
**Source:** 04.2-09-SUMMARY.md, HAOO commit 14f8d00

### Copy a value through stdin and `cmp` BEFORE deleting the source
Moving the three PostHog build variables compared captured JSON with `cmp` before the originals were
deleted, so a wrong key was impossible rather than unlikely.

**When to use:** Migrating any configuration value between systems where the source will be destroyed.
**Source:** 04.2-09-SUMMARY.md

### Guard every `cd "$VAR"` with `: "${VAR:?}"`
`cd` with an unset variable is a no-op that returns success — a verification meant for one repository
then runs in the other and reports green.

**When to use:** Every multi-checkout workflow. The phase's `04.2-split-env.sh` opens every verify
command this way.
**Source:** 04.2-01-SUMMARY.md, 04.2-split-env.sh

### Read checkout identity from the tree, not from argument order
The disjointness auditor reads `CNAME` to identify which checkout it is looking at, so passing the
same checkout twice is refused rather than reported as trivially disjoint.

**When to use:** Any tool taking two paths that must be different things.
**Source:** 04.2-08-SUMMARY.md

### Demonstrate falsifiability rather than asserting it
The disjointness guard was deleted in each repository, the pinning case watched go red, and the guard
restored.

**When to use:** Any new gate. A gate never seen to fail is a gate nobody knows works.
**Source:** 04.2-08-SUMMARY.md

## Surprises

### The Pages site was already bound to the wrong domain leg before anyone set it
`gh api repos/KaruguDev/HAOO/pages` reported a site bound to `www.haoo.online` — the leg the contract
did NOT record at the time.

**Impact:** Corrected with an explicit `PUT`. A plan that assumed an unset custom domain would have
silently shipped the wrong leg.
**Source:** 04.2-02-SUMMARY.md

### The counterpart redirect did not appear immediately
`https://www.haoo.online/` returned 404 minutes after the apex began serving 200, though the contract
states Pages supplies the counterpart redirect automatically.

**Impact:** Recorded rather than reacted to, and explicitly NOT treated as a reason to hand-roll a
second recovery document. It had resolved by the time 04.2-09 measured the domain gate.
**Source:** 04.2-02-SUMMARY.md

### The owner report had never once run successfully
It was written, tested, reviewed and shipped across two phases without a single live execution.

**Impact:** A whole feature was carried as "done" while being non-functional. Only a UAT checkpoint
that actually ran it surfaced this.
**Source:** 04.2-UAT.md gap G-04.2-9

### PostHog injects a LIMIT and OFFSET the caller never wrote
A probe submitting `SELECT 1` returned `hogql` of `SELECT\n    1\nLIMIT 101\nOFFSET 0`.

**Impact:** The strongest possible vindication of the existing refusal to let `hogql` substitute for
the query echo — it is demonstrably a rewrite. It also falsified the recorded claim that "the default
row limit is 100"; observed 101.
**Source:** 04.2-UAT.md gap G-04.2-9, ZPH commit 3b08e3d

### A signed-off verification breaks the very superset its own follow-up requires
Sign-off produces the UAT, coverage matrix and verification report — all ZPH-only — invalidating the
precondition D37 cited for deletion.

**Impact:** A latent data-loss instruction, found only because verification re-measured instead of
citing. Fixed structurally.
**Source:** 04.2-VERIFICATION.md finding W-1

### Three independent content blockers on one machine
Adblock Plus, a browser-extension VPN, and Vivaldi's built-in blocker — the last of which survives
disabling extensions AND private browsing.

**Impact:** Four diagnostic rounds, and a near-miss on recording a false negative. `curl` from the
same machine succeeded throughout, which is what eventually localised the fault to the browser.
**Source:** 04.2-VERIFICATION.md, 04.2-DEFERRED-ITEMS.md D41

### A summary contradicted itself about its own allowlist size
`04.2-08-SUMMARY.md`'s self-check says 19 entries where the body says 26.

**Impact:** Caught by the next plan reading it rather than by any gate. Recorded rather than silently
corrected, since the summary is a historical record of a completed plan.
**Source:** 04.2-09-SUMMARY.md

### Recorded figures reproduced EXACTLY under independent re-measurement
Verification re-measured every claim against both trees, both GitHub repos and both live sites rather
than trusting any summary: 102/26/26/0 violations, chunks at 207,627 and 179,611 bytes, HAOO root
4,147 B, retired doc 4,353 B, brochure 2,160,873 B, certificate CN and both SANs.

**Impact:** Reproduced exactly, not approximately. That is unusual enough to be worth recording — it
is the payoff of the measure-don't-assert discipline, and it is why the two findings that DID surface
(W-1, W-2) are credible rather than noise.
**Source:** 04.2-VERIFICATION.md
