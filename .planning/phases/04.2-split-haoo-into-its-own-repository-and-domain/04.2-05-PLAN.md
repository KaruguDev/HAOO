<objective>
Make the owner report's numbers mean what its headings say, now that the analytics project spans two
hostnames.

The measured constraint is unusually sharp. The project's transport reducer copies exactly three
named property keys into a fresh literal and drops everything else, and the vendor's page-URL, host,
path and referrer properties are all set client-side before that reducer runs. There is therefore no
host dimension on the wire and none in the query language — a host filter would match zero rows on
every event this project has ever sent, including the ones already recorded from the parent hostname.
The only discriminator that exists is the timestamp.

That is not a limitation to route around. It is the property chokepoint two privacy requirements rest
on, working correctly. The answer is a repository-owned cutover day applied as a lower bound to every
query, and a sentence in the report saying so.

Purpose: an owner reading an all-time count is reading HAOO-domain history, and knows it.
Output: a bound in both queries, a truthful provenance sentence, and a superseded caveat withdrawn
with its successor named.
</objective>
