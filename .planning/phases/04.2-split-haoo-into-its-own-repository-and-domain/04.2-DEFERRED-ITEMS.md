recorded out of band so a later reader can tell a **recorded** reduction from an unnoticed
regression.

## D1 — The per-file static boundary map lost two keys with the sources they mapped

**Found during:** `04.2-02` Task 1 (the single prune-and-narrow commit `d75724c`)
**File:** `HAOO: src/test/build-output.test.ts` — `const PRODUCT_SOURCE_BOUNDARY`, applied by
`it('keeps the product surface inside its narrowed static boundary')`

**Measured before/after: 17 keys → 15 keys.** The two removed, verbatim from the diff:

```
-  'src/components/ProductsSection.tsx': FULL_BOUNDARY,
-  'src/products/registry.ts': FULL_BOUNDARY,
```

Narrowed **per file**. `ALWAYS_FORBIDDEN`, `NETWORK_FORBIDDEN`, `PROVIDER_FORBIDDEN`,
`FORM_MARKUP_FORBIDDEN`, `MEASUREMENT_PRIVACY_FORBIDDEN`, `FULL_BOUNDARY` and
`MEASUREMENT_FACADE_BOUNDARY` are byte-unchanged, and the second loop in the case — the one
asserting every entry except the audited measurement facade still carries the whole
always-forbidden group — is unchanged and now runs over fifteen entries.

**Note the plan's figure was wrong.** `04.2-02-PLAN.md` predicted "eighteen-to-sixteen". The map
held **seventeen** keys before this commit (`awk '/^const PRODUCT_SOURCE_BOUNDARY/,/^};/' … |
grep -c "^  'src/"` → `17`), so the true narrowing is 17 → 15. The plan's acceptance criterion
naming sixteen is therefore unsatisfiable as written; the criterion it was standing in for — that
the map contains exactly the surviving product sources and that the case's non-empty source guard
fires for every one of them — is satisfied and green.

**Why it will fire:** it already did, by design. The map's `expect(source, relativePath).not.toBe('')`
guard goes red the instant a mapped source leaves the tree, which is precisely why the prune and
this narrowing had to be one commit rather than two.

**When it will fire:** it cannot fire again in this repository. It fires in ZERO-PAPER HUB the
moment that repository's copy of this suite is reduced without registering `ProductsSection.tsx`
and `registry.ts`, which are the two files that repository keeps.

**Not fixed here because:** nothing to fix — this is the recorded form of the fix. The alternative
(deleting the regex groups rather than the keys) is the anti-pattern Phases 2 and 3 established
against: it would have widened what the surviving fifteen sources are allowed to do.

**Suggested handling in `04.2-06`:** when the ZERO-PAPER HUB tree is reduced, that repository's map
keeps `ProductsSection.tsx` and `registry.ts` and drops the HAOO-only keys the same way — per file,
regex groups untouched. Both maps together must still cover every product source across the two
repositories; the union is the invariant, not either half.

## D7 — Twelve bare `/products/haoo/` jsdom paths remain, and one of them cannot move without weakening

**Found during:** `04.2-03` Task 2 (commit `874acd0`)
**File:** `HAOO: src/test/measurement-page.test.tsx` (13), `HAOO: src/test/measurement.test.ts` (2 —
both moved, see below)

**Measured before/after, 2026-09-06.** Plan `04.2-03` re-pointed **13 simulated page ORIGINS** —
absolute URLs carrying `www.zero-paperhub.com` — from the retired nested path to
`https://www.haoo.online/`. It also moved the **3 path literals forced into lockstep** by that
change, because the campaign normalizer replaces history state with
`${url.pathname}${url.search}${url.hash}` and a root origin produces a root pathname:

| File | Literal | Before | After |
|---|---|---|---|
| `measurement.test.ts:429` | parameterized campaign row's `replaceState` arg | `/products/haoo/#details` | `/#details` |
| `measurement.test.ts:445` | case-variant row's `replaceState` arg | `/products/haoo/?keep=yes` | `/?keep=yes` |
| `measurement-page.test.tsx:349` | page-memory campaign case's `replaceState` arg | `/products/haoo/` | `/` |

**Still carrying the retired path: 12 literals, all in `measurement-page.test.tsx`** — lines 72,
243, 258, 1049, 1164, 1475, 1488, 1501, 1512, 1524, 1532, 1546. These are jsdom paths on jsdom's
own default origin; none of them names a hostname, so none of them is in scope for the truth "no
file the HAOO repository builds, tests or publishes names the parent site's hostname" — that truth
is met, and `git grep -l 'zero-paperhub' -- ':!*.md' ':!package-lock.json'` returns **0**.

**Why it will fire:** it will not fire as a test failure. It fires as a *reader* problem: after this
plan the suite simulates the product page at two different locations — `https://www.haoo.online/`
in every case that names a host, and `/products/haoo/` in twelve cases that do not. The second is a
path this repository stopped serving at `04.2-02` and which the split contract records as
deliberately 404ing. A fixture simulating a 404 is a fixture that has quietly stopped describing
the system.

**When it will fire:** the moment someone reads `measurement-page.test.tsx` and tries to decide
which of the two locations is deliberate. It cannot fire as red.

**Not fixed here because moving them would WEAKEN an assertion, which SC "no assertion lost
strength" forbids.** Measured: `measurement-page.test.tsx:243` navigates to
`/products/haoo/?utm_source=Partner&…` and `:258` then asserts
`expect(window.location.pathname).toBe('/products/haoo/')` — that the utm-stripping preserved the
path. Re-pointed to the root that assertion becomes `toBe('/')`, **which is jsdom's default
pathname**: it would pass even if the stripping under test never ran at all. That is precisely the
"prove the subject is non-empty before asserting absence" failure this project guards against
(cf. T-04.2-12, and `04.2-02`'s vendor-chunk partition). Moving the other eleven while leaving that
one would split a coherent fixture family across two conventions, which is worse than leaving all
twelve — so all twelve stay, together, recorded here.

**Suggested handling:** owner's choice, not this phase's. Two coherent options: (a) leave them and
add one comment at the top of the file recording that these paths are jsdom scaffolding on jsdom's
origin and are deliberately not the published path; or (b) re-point all twelve **and** replace
`:258`'s pathname assertion with one that cannot pass on the default — for example asserting the
full `href` including the emptied search, or asserting `window.location.search` is `''` after a
non-empty search was navigated to. Option (b) is the stronger end state and is a self-contained
change; it was out of scope for `04.2-03`, which was scoped to hostname literals.
