# Phase 04.2 — Split Contract

**Written:** 2026-09-05 (plan 04.2-01, task 3)
**Status:** binding for plans 04.2-02 through 04.2-09.

This document records the structural choices that must be made once and read many times. Every
later plan in this phase reads the hostname, the document path, the asset directory, the repository
name and the retired-path disposition **from here** rather than re-deriving them. Re-deriving is how
the canonical URL, the two Open Graph URLs, the Twitter image, the form source line, the ZERO-PAPER
HUB card link, the `CNAME` file and the recovery document's target end up disagreeing about one
hostname.

Two of the four choices in `## Domain`–`## Retired path` are **not** the planner's recommended
defaults. Where that is so it is called out explicitly, because plan text written against the
default is now wrong and the affected plan must do work it was not written to do.

## Domain

**Chosen leg: the apex, `haoo.online`.** (Task 2 answer (a); the planner's recommended default.)

- The `CNAME` file in the **HAOO** repository contains exactly one line: `haoo.online`
- The `CNAME` file in the **ZERO-PAPER HUB** repository is unchanged: `www.zero-paperhub.com`

Every canonical URL, `og:url`, `og:image`, `twitter:image`, brochure link, form source line and
ZERO-PAPER HUB Products-card href written by this phase resolves against `https://haoo.online/`.

**GitHub Pages supplies the counterpart redirect for the other leg automatically.** `www.haoo.online`
will redirect to the apex without any configuration, record or document from us. This is the only
real 3xx GitHub Pages emits, and it is domain-level, never path-level (see `## Retired path`).
**No second recovery document is to be built for the `www` leg.** A plan that adds one is adding a
file to do a job the platform already does.

### Mail routing — decided, executed outside this phase

`haoo.online` has no MX records today, while `zero-paperhub.com` has MX at `privateemail.com`. With
no MX, RFC 5321 implicit-MX fallback delivers to the A record, which is GitHub Pages, which runs no
SMTP — so mail to `info@haoo.online` very likely does not arrive. That address is the destination of
the qualification-form fallback, the `mailto:` onboarding link and a `noscript` recovery link.

**Owner decision (2026-09-05): point the HAOO MX at `mx1.privateemail.com` / `mx2.privateemail.com`,
matching `zero-paperhub.com`.**

This is recorded as a decision only. **The DNS change is out of this phase's scope** — it belongs to
Phase 5 / LEAD-07. Plan 04.2-04's disclosure checkpoint may reference this line; no plan in this
phase performs the change or asserts against it. (RESEARCH assumption A7: the non-delivery is
inferred from DNS, not confirmed by a test send.)

partition quietly stops being a partition over project code.

`brochure/` is a directory Vite does not own, so the partition stays clean. This reasoning is
retained rather than deleted because it governs **any** future asset move in either repository, not
just this one — see also plan 04.2-08, whose disjointness check reads the built tree.

### History strategy

- **D-01 — the HAOO repository is a full clone plus an ordinary deleting commit.** Every commit is
  preserved; the tip commit deletes the non-HAOO half. No history rewriting, so every SHA cited
  across `.planning/` still resolves and `git blame` / `git log --follow` keep working on every HAOO
  file. Accepted cost: HAOO's history contains commits that no longer touch anything in its tree,
  and roughly 32 MB of `.git`.
- **D-02 — HAOO source leaves ZERO-PAPER HUB by an ordinary deleting commit, never by a rewrite.**
  Past commits keep the HAOO files; the working tree does not. SPLT-01 is a claim about what each
  repository *builds and ships*, and that claim stays true under a normal deletion. A `filter-repo`
  rewrite would have force-pushed over every existing clone and broken the SHA citations.
- **D-03 — `.planning/` moves whole** to the HAOO repository. All five phases are HAOO work, so the
  GSD record follows the product. ZERO-PAPER HUB starts with a clean `.planning/` when it next needs
  one.

The four values every later plan depends on live in a **sourceable file** beside this document:


It exports exactly `ZPH_CHECKOUT`, `HAOO_CHECKOUT`, `HAOO_REPO` and `HAOO_HOST`, and nothing else.

`$HAOO_CHECKOUT`, and no two plans in the same wave operate in it.** Plan 04.2-02 creates it; every
subsequent plan uses it in place. Two plans writing the same checkout concurrently would interleave

Every `<verify>` command in plans 04.2-02 through 04.2-09 opens with:


That guard exists because `cd "$VAR"` with `VAR` unset is a **no-op that returns success** — it

**Chosen: the four assets under the retired `/products/haoo/` path are LET GO. Nothing is copied
into the ZERO-PAPER HUB tree.** (Task 2 answer (d).)

**This is NOT the planner's recommended default.** The default copied the four assets into ZPH's

The owner chose the 404 instead.

**Consequences, accepted:**

- Every already-published brochure URL under `https://www.zero-paperhub.com/products/haoo/` breaks at

  prospects may hold as a bookmark. This is the accepted cost of the choice.

- Two upsides: the ZERO-PAPER HUB tree stays ~2.3 MB smaller, and `shared-scaffold.txt` (plan
  04.2-08) needs **no asset exception** — the SPLT-01 disjointness check has nothing extra to
  forgive.

**This decision does NOT repeal D-12.** D-12 governs the retired *page*, not the four *asset files*.
Plan 04.2-07 still ships `public/products/haoo/index.html` in the ZERO-PAPER HUB repository: a
minimal recovery document carrying `<link rel="canonical">` to the HAOO page, a meta refresh, and a
visible link for any visitor the refresh does not carry. It carries no measurement, no form and no
product content. **The stub's links must point at the new root-level `haoo.online` asset URLs from
`## Published document path`, never at the dead ZPH paths.** Only the four asset files are dropped.

### The mechanism constraint

**GitHub Pages emits no per-path 3xx.** The recovery document is a client-side redirect used as a
documented last resort, not a preference.

- Pages supports no user-supplied server configuration `[CITED: docs.github.com — Pages does not
  support .htaccess or .conf]`.
- **An instant (0-second) meta refresh is read by Google Search as a permanent redirect; a delayed
  one is read as temporary** `[CITED: developers.google.com/search/docs/crawling-indexing/301-redirects]`.
  Use zero seconds. The widely repeated community claim that "meta refresh is a 302 by default" is
  contradicted by Google's own current documentation and must not be carried into any plan.
- `rel="canonical"` is **complementary, not a substitute**. D-12 correctly ships both.
- The only real 3xx Pages emits is the automatic apex↔`www` counterpart redirect — domain-level, and
  unavailable for a path.

**Non-mechanisms on this host. No later task may reach for any of them:** `_redirects` (Netlify/
Cloudflare Pages), `netlify.toml`, `.htaccess` (Apache), and `jekyll-redirect-from` — the last
generates HTML meta-refresh pages rather than HTTP 301s, and requires a Jekyll build this repository
does not run `[CITED: github.com/jekyll/jekyll-redirect-from]`. All four are real mechanisms on
*other* hosts, which is exactly why someone ships one here and it silently does nothing.

Related: `public/.htaccess` and `public/CNAME.txt` are tracked in ZERO-PAPER HUB today and both are
inert on Pages (Pitfall 7). They are actively misleading during this phase — a reader looking for
"how does `/products/haoo/` resolve on refresh?" finds the `.htaccess` SPA rewrite and concludes
there is a rewrite rule. There is not; the path resolves because `dist/products/haoo/index.html` is
a **physical file**. Delete or annotate both in the ZPH reduction commit.

## Shared scaffold

Nineteen paths legitimately exist in **both** repositories. This set is the crux of SPLT-01, which
says "*neither suite reading a file the other owns*". Toolchain scaffolding is owned by **neither**
half — it is owned by the repository. A verification that treats these as violations fails for the
wrong reason, which is why the allowlist is written down here rather than discovered at verification
time.

```
package.json
package-lock.json
tsconfig.json
tsconfig.app.json
tsconfig.node.json
eslint.config.js
postcss.config.js
tailwind.config.js
vite.config.ts
vitest.config.ts
.gitignore
AGENTS.md
README.md
.github/workflows/deploy.yml
src/main.tsx
src/index.css
src/vite-env.d.ts
src/test/setup.ts
CNAME
```

**The fenced block above is the exact content plan 04.2-08 copies into `shared-scaffold.txt` in both
repositories.** One bare path per line, no bullets, no backticks, no blank lines inside the fence.
The format is load-bearing: a check reads it, and the entry count is mechanically verified. Prose
belongs above or below the fence, never inside it.

**This list is closed. An entry is added by declaring toolchain ownership — a file the repository
owns rather than either product half — never by adding a file the other half also happens to need.**
(Modelled on the closed-list discipline documented at `src/test/focus-contrast.test.ts:27-33`, where
the list is kept closed by registering each new component rather than by widening the token set, so
a style that is never measured cannot ship.) The same logic applies here: a file admitted because
"both sides need it" is precisely the coupling SPLT-01 exists to forbid.

`CNAME` is on the list as a **path**, not as a value. Both repositories have the file; the two hold
different hostnames (`haoo.online` and `www.zero-paperhub.com`), and `build-output.test.ts:742-747`
pins one literal per side. That per-side pin is the guard against Pitfall 2.

**No asset duplication is recorded here.** Task 2 answer (d) lets the retired ZPH asset URLs 404
rather than copying the four files, so there is no exception for the disjointness check to forgive.
Had the default been taken, the four `public/products/haoo/` assets would have needed an entry with
its reason.

The check itself (RESEARCH, "Verifying the two trees are disjoint"). **Written as an indented
block, not a fenced one, deliberately** — the extraction that reads this section takes fenced
content, and a second fence here would put these three lines into `shared-scaffold.txt`:

    comm -12 <(git -C zero-paperhub ls-files | sort) <(git -C haoo ls-files | sort) \
      | grep -v -x -F -f shared-scaffold.txt
    # must print nothing
