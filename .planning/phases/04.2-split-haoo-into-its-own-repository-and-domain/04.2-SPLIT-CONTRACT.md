# Phase 04.2 — Split Contract

**Written:** 2026-09-05 (plan 04.2-01, task 3)
**Status:** binding for plans 04.2-02 through 04.2-09.

This document records the structural choices that must be made once and read many times. Every
later plan in this phase reads the hostname, the document path, the asset directory, the repository
name and the retired-path disposition **from here** rather than re-deriving them. Re-deriving is how
the canonical URL, the two Open Graph URLs, the Twitter image, the form source line, the ZERO-PAPER
HUB card link, the `CNAME` file and the recovery document's target end up disagreeing about one
hostname.

Two of the four choices in `## Domain`–`## Retired path` are **not** the planner's recommended
defaults. Where that is so it is called out explicitly, because plan text written against the
default is now wrong and the affected plan must do work it was not written to do.

### History strategy

- **D-01 — the HAOO repository is a full clone plus an ordinary deleting commit.** Every commit is
  preserved; the tip commit deletes the non-HAOO half. No history rewriting, so every SHA cited
  across `.planning/` still resolves and `git blame` / `git log --follow` keep working on every HAOO
  file. Accepted cost: HAOO's history contains commits that no longer touch anything in its tree,
  and roughly 32 MB of `.git`.
- **D-02 — HAOO source leaves ZERO-PAPER HUB by an ordinary deleting commit, never by a rewrite.**
  Past commits keep the HAOO files; the working tree does not. SPLT-01 is a claim about what each
  repository *builds and ships*, and that claim stays true under a normal deletion. A `filter-repo`
  rewrite would have force-pushed over every existing clone and broken the SHA citations.
- **D-03 — `.planning/` moves whole** to the HAOO repository. All five phases are HAOO work, so the
  GSD record follows the product. ZERO-PAPER HUB starts with a clean `.planning/` when it next needs
  one.

### The mechanism constraint

**GitHub Pages emits no per-path 3xx.** The recovery document is a client-side redirect used as a
documented last resort, not a preference.

- Pages supports no user-supplied server configuration `[CITED: docs.github.com — Pages does not
  support .htaccess or .conf]`.
- **An instant (0-second) meta refresh is read by Google Search as a permanent redirect; a delayed
  one is read as temporary** `[CITED: developers.google.com/search/docs/crawling-indexing/301-redirects]`.
  Use zero seconds. The widely repeated community claim that "meta refresh is a 302 by default" is
  contradicted by Google's own current documentation and must not be carried into any plan.
- `rel="canonical"` is **complementary, not a substitute**. D-12 correctly ships both.
- The only real 3xx Pages emits is the automatic apex↔`www` counterpart redirect — domain-level, and
  unavailable for a path.

**Non-mechanisms on this host. No later task may reach for any of them:** `_redirects` (Netlify/
Cloudflare Pages), `netlify.toml`, `.htaccess` (Apache), and `jekyll-redirect-from` — the last
generates HTML meta-refresh pages rather than HTTP 301s, and requires a Jekyll build this repository
does not run `[CITED: github.com/jekyll/jekyll-redirect-from]`. All four are real mechanisms on
*other* hosts, which is exactly why someone ships one here and it silently does nothing.

Related: `public/.htaccess` and `public/CNAME.txt` are tracked in ZERO-PAPER HUB today and both are
inert on Pages (Pitfall 7). They are actively misleading during this phase — a reader looking for
"how does `/products/haoo/` resolve on refresh?" finds the `.htaccess` SPA rewrite and concludes
there is a rewrite rule. There is not; the path resolves because `dist/products/haoo/index.html` is
a **physical file**. Delete or annotate both in the ZPH reduction commit.

### Ground B — ratified path collisions with divergent content (3)

```
src/App.tsx
src/test/build-output.test.ts
src/test/focus-contrast.test.ts
```

**These are not shared files, and the distinction is load-bearing.** They are the same PATH holding
entirely different content, because both repositories descend from the same Vite React scaffold.
ZERO-PAPER HUB's `src/App.tsx` contains ZERO-PAPER HUB source; HAOO's contains HAOO source. SPLT-01
is a claim about **content ownership**, not path occupancy, so neither tree contains the other's
source and the requirement is satisfied. Measured 2026-09-06: 17 ZPH build-output cases vs 40 in
HAOO; one registered focus source vs six.

**How Ground B decays, and what is done about it.** A Ground A entry is safe indefinitely — several
are deliberately identical. A Ground B entry is safe only while its two copies stay **divergent**. If
one ever CONVERGES, that is a genuine SPLT-01 violation, and a plain path allowlist is blind to it
because the path is forgiven either way. So `verify-tree-disjointness.mjs` does not merely subtract
these three: it asserts per entry that the two copies are **not byte-identical**, and reports
convergence as a violation. **Never move an entry between grounds to silence a finding** — moving a
converged file to Ground A would declare a genuine violation to be scaffolding.

### The rule, unchanged

**This list is closed. An entry is added on exactly one of the two grounds above — toolchain
ownership, or a ratified divergent-content collision — never because "both halves need it."**
(Modelled on the closed-list discipline at `src/test/focus-contrast.test.ts:27-33`.) A file admitted
because "both sides need it" is precisely the coupling SPLT-01 exists to forbid.

**The two fenced blocks above are the exact content of `shared-scaffold.txt` in both repositories,**
which additionally carries a one-clause reason per entry as `#` comments and marks the two grounds
with machine-readable `# @ground:` directives. One bare path per line inside the fences, no bullets,
no backticks, no blank lines. The format is load-bearing: a check reads it, and the entry count is
mechanically verified at **26**. Prose belongs outside the fences, never inside.

`CNAME` is on the list as a **path**, not as a value. Both repositories have the file; the two hold
different hostnames (`www.haoo.online` and `www.zero-paperhub.com`), and `build-output.test.ts`
pins one literal per side. That per-side pin is the guard against Pitfall 2.

**No asset duplication is recorded here.** Task 2 answer (d) lets the retired ZPH asset URLs 404
rather than copying the four files, so there is no exception for the disjointness check to forgive.

whose content **names** the product are the card registry and the recovery document. Plan `04.2-08`
measured that at **eleven files, not two**, and showed it self-defeating: it flagged the disjointness
checker and its own allowlist for naming what they exist to guard against, and it flagged the two
suites whose entire purpose is proving HAOO is gone.

**The assertion is now that the ZERO-PAPER HUB tree ships no HAOO PRODUCT SOURCE** — not that no file
may name the product. Tooling, guards, tests, configuration and CI are exempt: referencing the
product in order to police its absence is their job.

The exempt class is **derived from what a file is, never enumerated**. An exemption listing today's
offenders would go stale silently, which is the vacuous pass the check exists to refuse. Product
source is: a file under `src/` or `public/`, or a root-level `*.html`, that is not one of the two
named carriers, not a test, not an ambient declaration, and not documentation. Tooling (`scripts/`),
CI (`.github/`), the root manifests, the tool configs and the lockfile fall outside that class **by
construction**, without being listed.

Two probes run over comment-stripped content — a comment recording that the product LEFT is not
product source, and the tree is full of them by design:

2. a closed list of **HAOO product symbols** (`HAOO_PRODUCT`, `ProductPage`, `QualifyForm`,
