## Visual Direction

The measurement disclosure is a visible trust surface, not legal fine print and not a consent banner. It belongs inside the existing `#qualify` journey at the point where a visitor decides whether to send details, while a footer link makes it discoverable to visitors who use assisted or self-onboarding without reaching the form.

Keep the surface calm and readable: a pale HAOO inset containing one always-visible notice followed immediately by a native expandable block. Inside the expanded block, use short paragraphs, labelled lists, and one outlined clear action. Do not introduce a cookie-banner silhouette, sticky overlay, modal interruption, toggle wall, provider logo, illustration, data dashboard, or technical JSON display.

The disclosure must visually distinguish four truths without implying that they are one data flow:

1. Bare aggregate event names may be emitted to a configured provider; Phase 3 defaults to a no-op provider.
2. Coarse engagement context is remembered locally in this browser.
3. Allowlisted campaign values are read once, normalized, kept only for the page lifetime, and removed from the address bar.
4. No engagement summary is attached to the qualification submission yet; that remains Phase 4.

**Source:** CONTEXT D-01, D-02, D-09 through D-16; MEAS-04; approved D-16 human checkpoint on 2026-08-30.

## Information Architecture and Responsive Layout

### Placement and order

1. Keep the existing `#qualify` section and its one-line collection notice immediately above the submit control.
2. Replace only the Phase 2 forward-looking page-context sentence with the owner-approved Phase 3 sentence in the existing notice surface.
3. Place `<details id="haoo-measurement-disclosure">` immediately after that visible sentence and before the submit control. Its first child is `<summary>How we measure this page</summary>`.
4. Inside the expanded content, use this fixed order:
   a. one sentence separating aggregate event measurement from local browser context;
   b. `Signals this page can count` — all ten signal meanings, one line each;
   c. `What this browser remembers` — the three coarse concepts and two approved derivation fields;
   d. `Campaign information` — exact allowlist and page-lifetime/URL-removal behavior;
   e. `What we never collect for measurement` — the locked exclusion list;
   f. current form-summary boundary sentence;
   g. `Clear what this page remembers` control;
   h. persistently mounted clear-status region.
5. Add `How we measure this page` to the product footer link group before `Back to ZERO-PAPER HUB`. It anchors to `#haoo-measurement-disclosure`.

### Responsive behavior

- Use one column at every width. No two-column collected/never-collected comparison: serial reading order is clearer at 320px and 200% zoom.
- Lists use normal wrapping and visible bullets; no horizontal scroll, fixed-width code labels, tables, pills, or truncation.
- `summary` and the clear control are full width below `md`; the clear control may become auto width from `md` upward.
- The footer link wraps within the existing flex group and never forces horizontal overflow.
- Do not add entrance animation. Native disclosure opening is immediate; no height animation or transform is permitted.

**Source:** CONTEXT D-13 through D-15; `03-RESEARCH.md` native disclosure pattern; existing `ProductPage` and `QualifyForm` structure.

## Interaction Contract

### Disclosure

- The disclosure is collapsed by default. Activating its native summary toggles it without a custom React open-state mirror.
- Keyboard interaction is platform-native. Do not add `role="button"`, `aria-expanded`, or key handlers to `summary`; duplicating native semantics is prohibited.
- The footer link opens the same disclosure instance and navigates to its fragment. No duplicate disclosure appears in the footer.
- Reaching the target must respect the existing `scroll-mt-4` anchor offset. The disclosure summary remains the next keyboard-focusable element; fragment navigation does not force focus.
- Opening or closing the disclosure is not itself measured. Reading privacy information must not create a new analytics signal.

### Clear action

- Activating `Clear what this page remembers` immediately clears the one namespaced stored record and the module's current page-memory record. It requires no confirmation dialog because the removed data is bounded, locally reproducible engagement context and the action affects no lead/form data.
- On successful or already-empty clear, set the nearby status to `What this page remembered has been cleared.` The same result copy is deliberate: it reveals nothing about prior history and keeps the action idempotent.
- If persistent removal is blocked, clear the module's page-memory context and set status to `This page stopped using remembered context for this visit. Your browser did not allow us to clear its saved copy.` Do not throw, disable the page, hide onboarding, or claim the saved copy was removed.
- Repeated activation remains enabled and produces the same truthful status. There is no loading state, spinner, toast, modal, undo timer, or page refresh.
- The clear action never clears form answers, validation state, submission state, campaign values already removed from the URL, or any browser data outside `zph.haoo.ctx.v1`.

### Failure and progressive enhancement

- Analytics provider unset/unknown: all disclosure and clear UI remains identical; valid events are discarded and no provider-error message appears.
- Storage unavailable at first access: the page uses page-memory context, the disclosure still renders, the clear control still clears that memory, and the journey remains complete.
- `replaceState` failure: the journey remains complete; no blocking UI error is shown. The disclosure describes intended normalization/removal behavior, never claims that a particular address bar was successfully rewritten.
- Default, hover, focus-visible, and active states are distinguishable without scale. Use color/underline changes no longer than 200ms; disable optional transitions under reduced motion.

**Source:** CONTEXT D-01, D-02, D-08, D-11 through D-14; MEAS-07; `03-RESEARCH.md` fail-open pattern.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Clear what this page remembers` |
| Empty state heading | Not applicable — this is a fixed disclosure, not a context viewer. The clear action stays available whether persistent context exists or not. |
| Empty state body | Not applicable — do not expose whether a prior local record existed. The idempotent clear result covers both states. |
| Error state | `This page stopped using remembered context for this visit. Your browser did not allow us to clear its saved copy.` |
| Destructive confirmation | `Clear what this page remembers`: no pre-action confirmation; post-action status is `What this page remembered has been cleared.` |

### Locked visible notice — owner-approved 2026-08-30

`This page remembers only coarse HAOO engagement signals — whether you visited before, roughly when you last visited, and whether you viewed or downloaded the brochure, started this form, contacted HAOO, or opened self-onboarding. These signals stay separate from your form answers, and no engagement summary is attached to this submission yet.`

This sentence replaces `qualifyCollectionNotePageContext()` and its forward-looking comment. It is rendered verbatim and remains separate from the existing FormSubmit processor sentence.

### Disclosure labels and framing

| Element | Copy |
|---------|------|
| Summary and footer link | `How we measure this page` |
| Intro | `We use a closed list of page signals for aggregate product learning and keep a separate, small context record in this browser. The page works if analytics or browser storage is unavailable.` |
| Signals heading | `Signals this page can count` |
| Browser heading | `What this browser remembers` |
| Campaign heading | `Campaign information` |
| Never-collected heading | `What we never collect for measurement` |
| Current summary boundary | `No engagement summary is attached to this form submission yet.` |
| Clear control | `Clear what this page remembers` |
| Clear success / already empty | `What this page remembered has been cleared.` |
| Clear blocked | `This page stopped using remembered context for this visit. Your browser did not allow us to clear its saved copy.` |

### Exact signal disclosure map

Each line maps one-to-one to the ten-name event union. Event identifiers are implementation details and do not appear in visitor copy.

| Signal meaning | Visitor-facing line |
|----------------|---------------------|
| HAOO page view | `That you viewed this HAOO page.` |
| Brochure preview | `That the brochure preview became available.` |
| Brochure open | `That you opened the brochure.` |
| Brochure download | `That you downloaded the brochure.` |
| Qualification start | `That you started the qualification form.` |
| Qualification submit | `That you tried to send the qualification form after it passed the page's checks.` |
| WhatsApp contact | `That you chose WhatsApp to contact HAOO.` |
| Phone contact | `That you chose phone to contact HAOO.` |
| Email contact | `That you chose email to contact HAOO.` |
| Self-onboarding | `That you opened HAOO self-onboarding.` |

The disclosure must say these signals are bare names with no attached form answers or visitor properties. Wording remains browser-observable: `viewed`, `became available`, `opened`, `downloaded`, `started`, `tried to send`, and `chose`; never `delivered`, `received`, `became a customer`, or `completed onboarding`.

### Browser-context copy requirements

State plainly that this browser remembers:

- whether the visit is `first`, `returning`, or `frequent`;
- whether the last visit was `today`, `this week`, `this month`, or `earlier`;
- whether the brochure was viewed or downloaded, the form was started, an assisted-contact channel was chosen, or self-onboarding was opened;
- a visit step capped at four and a day-only last-seen value, used only to calculate the coarse bands and remove context after about 180 days.

Follow with: `The capped visit step and day-only value never enter analytics events or form submissions.`

Campaign copy must name only `utm_source`, `utm_medium`, and `utm_campaign`, say that accepted values are lowercased and limited to short letters/numbers/hyphens, and say they are removed from the address bar after being read. Do not describe `utm_term` or `utm_content` as accepted.

The never-collected list must include: name; email address; phone number; organization; message text; role, county, timeframe, or exact portfolio values; UUIDs, cookies, fingerprints, or cross-site identifiers; raw click history; and any form answer attached to an analytics event.

**Source:** CONTEXT D-05 through D-16; MEAS-02 through MEAS-06; approved D-16 checkpoint.

### Resolved explicit contracts

- The visible collection notice always renders the owner-approved sentence; absence of analytics, storage, campaign values, or prior context never creates a blank notice.
- The visible collection notice renders immediately with the form and never shows a skeleton, spinner, progressive reveal, or delayed replacement.
- Form submission errors never remove, replace, or shorten the visible collection notice.
- The normal visible-notice state is the single owner-approved sentence rendered verbatim and wired into the submit control's accessible description.
- The visible notice is atomic copy: it renders completely or the contract test fails; no partial clauses or conditional fragments are permitted.
- The visible notice wraps naturally inside the 560px form measure and never clips, truncates, ellipsizes, or creates horizontal scrolling.
- The visible notice and inset grow vertically for long text at 320px and 200% zoom.
- An empty disclosure event map is a type/contract failure; production never renders a blank collected-signals section.
- Analytics, storage, campaign, or history failures never remove the disclosure; its static content remains readable.
- The populated disclosure renders ten event lines, five bounded context facts, campaign rules, the never-collected list, the summary boundary, and the clear action in fixed order.
- Event and disclosure mappings are total; missing product copy fails typecheck/tests rather than silently rendering a partial list.
- Disclosure paragraphs and lists use block flow, visible bullets, and wrapping with no tables, chips, fixed-width labels, clipping, or horizontal scrolling at 320px or 200% zoom.
- The collected-signals list renders exactly ten lines one-to-one with the event union; zero or any other cardinality is a contract-test failure.
- Disclosure paragraphs, list items, and summary labels wrap without fixed height, line clamp, truncation, or ellipsis.
- Persistent clear failure clears page memory and renders the locked truthful status without throwing, disabling the page, or hiding onboarding actions.
- The clear control and status region grow vertically when copy exceeds the container; reserved status height is a minimum rather than a clipping boundary.
- Clear-status and control labels wrap while preserving the 44px minimum interactive target.
- Without JavaScript, the footer measurement link remains a native fragment link to the disclosure summary; scripted expansion is progressive enhancement only.
- The footer's flex-wrap layout moves the measurement link onto another row before it can shrink, clip, or create horizontal overflow.
- The footer label wraps without truncation or ellipsis while preserving its 44px minimum target.

### Dismissed with reasons

- Visible-notice zero/one/many behavior is not applicable because it is one fixed sentence, not a runtime collection.
- Disclosure loading behavior is not applicable because all disclosure copy is local, static, and synchronously rendered.
- Clear-action loading behavior is not applicable because clearing is synchronous; the control is never disabled or relabelled as loading.
- Footer-link loading behavior is not applicable because it is a static native anchor with no fetched dependency.
