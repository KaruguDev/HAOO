<objective>
Turn the exploratory baseline into a gate: disposition every blocking finding by name, fix what is
this repository's to fix, and stand up the spec that will fail in future if any of them returns.

The dangerous move here is the cheap one. Every blocking finding can be made to disappear by editing
the tag list, adding a rule disable, or lowering the impact threshold — and every one of those makes
the gate green without making the page any more usable. The gate consumes the same factory and the
same impact set as the baseline for exactly that reason: it cannot be configured greener than the
run that found the problems.

Purpose: close the findings, or record who decided not to, in their own words.
Output: `e2e/axe-gate.e2e.ts`, any source fixes, and the triage record appended to `05-EVIDENCE-AXE.md`.

**Working directory: the HAOO checkout** (05-01, D-01/D-04). ZERO-PAPER HUB-side findings outside the
Products region are deferred by decision D-OQ-3 and are not fixed here.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gate configuration → gate result | The rule set, tag list and impact threshold decide what the gate can ever report; changing them is indistinguishable from fixing, in the result |
| owner's decision → the evidence record | An accepted risk crosses from a conversation into a permanent public record |
| committed fix → deployed page | The live specs measure production, so a fix that is not deployed is not measured |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05-66 | Repudiation | an accepted risk | high | mitigate | Acceptance is a `gate="blocking-human"` decision checkpoint, the reason is transcribed verbatim, and the gate expresses it as a named exception keyed on rule and node with a vacuity guard rather than as an invisible disable |
