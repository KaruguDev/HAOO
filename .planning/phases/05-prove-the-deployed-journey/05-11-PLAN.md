<objective>
Prove the recovery surfaces: the HAOO page with scripting unavailable, the retired-path document a
visitor reaches from an old bookmark, and the onboarding destinations a prospect falls back to.

Two disciplines govern this plan. **Resolve, never deliver** — the onboarding paths are proven to
resolve, not to deliver, because placing a call or sending a message reaches third-party systems this
project does not control and cannot cheaply re-run. And **recorded is not passed** — a third-party
host being down is not a defect in this project's markup, so it is recorded as an observation with
its measured status, while a missing, malformed or wrong-target link is a contract failure that fails
the run. The two must be distinguishable in the evidence, never collapsed into one verdict.

Purpose: the visitor who arrives with an old URL, or with scripting off, or after a failed form, must
still get where they are going.
Output: `e2e/recovery.e2e.ts` and `05-EVIDENCE-RECOVERY.md`.

**Working directory: the HAOO checkout** (05-01, D-01/D-04). The retired-path document is reached by
its live ZERO-PAPER HUB URL only; nothing is installed in that repository.
</objective>

  <action>
    Two describe blocks against the live retired-path URL.

    **Refresh neutralised.** Intercept the document response, take its body, strip the refresh
    directive from the markup, and fulfil the request with the rewritten body. Disabling scripting is
    not sufficient and must not be relied on: the refresh is a parser directive, not script, and at an
    instant delay there is no window in which to assert. Do both — strip the directive *and* disable
    scripting — so the assertion runs against the document a visitor sees when the enhancement does
    not carry them.

    In that state assert all five required statements are present as rendered, visible text: that the
    product has moved to its own domain; a working absolute link to the HAOO page whose visible text
    names the destination host; a working absolute link to the brochure artifact at its new host; a
    statement that the old sibling asset URLs are not retained and return not-found; and a statement
    that the visible links work whether or not the refresh runs. Assert visible rendered text, not
    markup presence — a statement present but not rendered is not a statement to a visitor.

    Then activate the visible HAOO link in that same state and assert the browser lands on the HAOO
    page with its top-level heading present. The refresh not running is the case the document exists
    for, so it is the case that must be proven.

    Record this whole block as a **modified-page measurement** and never conflate it with the
    as-served reading.

    **Structural assertions**, on the document as served:
    - the refresh delay is exactly the instant value, asserted as that exact number — an instant
      refresh reads as a permanent move and a delayed one reads as temporary, so the number is
      load-bearing;
    - a canonical reference and a no-index directive are both present;
    - the count of script elements is **exactly zero**, asserted as an exact number rather than as a
      maximum;
    - the refresh target, the canonical reference and the visible HAOO link's destination are asserted
      **equal to one another**, not each against a literal, so one edited target cannot silently split
      them. This mirrors what the built-tree suite already does and extends it to the deployed bytes.

    **Refresh permitted.** In a separate block with no interception, load the retired path and assert
    the browser lands on the HAOO page with its top-level heading present. This is the cross-repository
    navigation claim, end to end, and it is a separate assertion from the neutralised one.

    Record both readings, each labelled with its mode.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| old bookmark → the retired path | A visitor arrives at a ZERO-PAPER HUB URL expecting HAOO content that no longer lives there |
| retired-path document → the HAOO domain | A static document in one repository asserts destinations on the other repository's domain |

| page → analytics ingestion origin | A network dependency whose failure must not degrade the journey |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05-48 | Spoofing | the retired-path document's destinations | high | mitigate | The refresh target, the canonical reference and the visible link destination are asserted equal to one another, so one edited target cannot split them and silently send visitors somewhere else |
