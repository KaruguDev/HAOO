# Phase 04.1 Plan 06: Truthful Processor Disclosure Summary

**The visitor-facing disclosure now names PostHog and the United States as the analytics processor and jurisdiction, plus the per-page-load transport reference the wire actually carries, sourced through required product-data members that make omission a typecheck failure.**

## Accomplishments

- **The disclosure is true again about where the data goes.** D-08 moved measurement to PostHog Cloud US while the disclosure's only processor sentence still described the form's email forwarder. A visitor now reads that aggregate page signals are processed by PostHog in the United States.
- **The statement cannot be silently omitted.** `processorHeading` and `processorNote` are required members of `ProductMeasurementDisclosure`, ordered between the campaign and never-collected members so interface order matches render order. Deleting `processorNote` makes `npm run typecheck` exit 2 — verified by mutation probe and restored.
- **A false claim was removed from the never-collected list.** The list asserted that UUIDs are never collected for measurement while the payload carries a per-event `uuid` and a UUID-shaped `distinct_id`. Owner approved dropping the word; the ephemeral transport reference is now explained in the processor group rather than denied elsewhere.
- **The component stayed a shell.** `grep -c` for both `United States` and `PostHog` in `MeasurementDisclosure.tsx` returns 0. The existing contract that iterates every configured disclosure string and forbids it from the component source now covers the new copy automatically.
- **The changed MEAS-04 surface was re-verified, not assumed.** Six new assertions cover rendering, structural ordering, storage/event inertness, invariance across four runtime conditions, derivation from product data, and the no-live-values prohibition.

## Decisions Made

**Resolution of the D-10 deferral (Task 1, blocking-human checkpoint).** Two rulings, both owner-approved as byte-exact visitor-facing copy:

1. **Option `region-and-transport`.** Heading `Where this measurement is processed`; note naming both the United States and the temporary per-page-load reference. Chosen over `region-only` because the payload verifiably carries a project token and a transport reference, and the recipient-naming precedent this project already uses for the form processor argues for saying so at the point of collection.
2. **Amend the never-collected list.** The line `UUIDs, cookies, fingerprints, or cross-site identifiers.` becomes `Cookies, fingerprints, or cross-site identifiers.` This was raised during the checkpoint as a finding the plan had not anticipated: `stripToBareName` returns `{ ...result, properties }`, preserving PostHog's per-event `uuid`, and `distinct_id` is UUID-shaped. The old line was therefore a positive claim the wire contradicted, not merely an omission — which is what made `region-only` weaker than the plan presented it.

**The bundle pin is a derived assertion.** The plan said to add the note to "the approved notice segments". `APPROVED_NOTICE_BUNDLE_SEGMENTS` is specifically the collection notice split on the product name, so appending to it would have been wrong. Two explicit `expect(bundle).toContain(HAOO_PRODUCT.measurement.disclosure.processor*)` assertions were added instead, following the same derive-never-restate discipline documented on that constant.
