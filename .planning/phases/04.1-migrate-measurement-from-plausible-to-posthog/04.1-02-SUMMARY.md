## Decisions Made

- **Reason cells record the failure mode, not just the verdict.** `autocapture` is `@default true`; `capture_heatmaps` is `@default undefined` and therefore falls back to *remote configuration*; `capture_pageleave` is `@default 'if_capture_pageview'` and is off only because pageview is off. Each is a different way the lockdown could silently regress, so each reason names its own mechanism.
- **Levers that look like the privacy boundary are recorded as OPT-OUT rows.** `property_denylist` runs before `$process_person_profile` is appended and cannot be the contract; `sanitize_properties` is deprecated in favour of `before_send`; the `ip` option is documented as having no effect. Omitting them would leave the next reader free to reach for one believing it works.
- **`cookieless_mode` is opted out with its own reason.** It writes nothing to the browser, which reads as strictly better, but it makes the server derive an identifier from personal data and it silently ignores every event when the matching project setting is off — the dead-funnel failure D-05 exists to prevent.
- **The FormSubmit table was copied, not re-derived.** It was extracted from the Phase 4 file with `sed` and appended verbatim; re-typing it would have been an undeclared re-decision of a surface unrelated to this migration.
- **`REQUIRED_TABLES` was generated from `COVERAGE.md` by a throwaway script.** A transcription typo surfaces as "missing capability row", which reads like a documentation gap rather than a typo; generating the entries removed that class of error entirely.
- **Script identity was left alone.** The filename, the exported `auditPhase4Coverage`, and the "Phase 4 coverage audit" console message are unchanged — `src/test/haoo-report.test.ts` asserts the path, and renaming beyond the plan's declared scope would be an undeclared change.

## Verification Notes

One acceptance criterion in the plan was written as a command that cannot be satisfied, and was
executed in its corrected form:

- **Criterion:** "Every row matching `| OPT-OUT |` has a non-empty third cell — checkable with `awk -F'|' '/OPT-OUT/ { if ($4 ~ /^[[:space:]]*$/) exit 1 }'` exiting 0."
- **Problem:** the awk pattern is `/OPT-OUT/`, not `/\| OPT-OUT \|/`, so it also matches prose containing the token. The operational boundary is *required* by another criterion in the same plan to contain the sentence "Production analytics enablement remains OPT-OUT", and that prose line has no fourth pipe-delimited field — so `$4` is empty and the command exits 1 on any file that satisfies the boundary check. The same command exits 1 against the Phase 4 `COVERAGE.md` for the same reason.
- **Resolution:** run the criterion's stated intent — `awk -F'|' '/\| OPT-OUT \|/ { if ($4 ~ /^[[:space:]]*$/) exit 1 }'` — which is scoped to table rows. It exits 0. The verifier's own `OPT-OUT reason is blank` check covers the same property inside the required tables, and the blank-reason mutation probe confirms it fires.
