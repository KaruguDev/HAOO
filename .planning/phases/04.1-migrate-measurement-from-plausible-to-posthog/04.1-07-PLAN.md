<objective>
Give the owner everything the code cannot do for them, and make sure no claim from Phase 4
is left pointing at a provider that no longer exists.

Two of this phase's privacy outcomes are only reachable through the PostHog project UI —
suppressing server-side geo-IP enrichment, and confirming live that one visitor action
produces exactly one name-only event. Research flagged the first as a blocking finding
rather than an accepted caveat, precisely because a guarantee that quietly depends on a UI
toggle reads like a code guarantee to everyone downstream.

The migration is unusually clean on the data side: the previous provider was never activated
in production, so there is no dashboard to tear down, no history to lose, and no data
migration to plan. That should be recorded so nobody plans one.

Purpose: the human gates are named, findable, and honestly scoped.
Output: owner setup instructions, migrated README sections, restated Phase 4 claims, and a
blocking owner action for the two settings the code cannot assert.
</objective>

  <action>Enable "Discard client IP data" on the PostHog project, and acknowledge that the automatic-capture toggles are left alone.</action>
  <instructions>
    Everything automatable is already done: the adapter disables the remote-configuration
    fetch and sets every automatic-capture option to an explicit off, the readback refuses
    initialization if any of them resolves wrong, and the wire-level regression proves only
    the ten bare names leave the page. Two things remain that no code in this repository can
    establish or assert.

    **1. Discard client IP data — action required.**
    PostHog enriches every ingested event server-side with geo-derived location fields
    computed from the visitor's IP address. That is exactly the class of exact-location value
    the closed-allowlist requirement prohibits, and it arrives by a route no client-side
    configuration controls: the SDK option that once suppressed it is documented as having no
    effect, and the only remaining client-side lever would add a property to the payload,
    which would break the bare-name contract this phase just proved twice.

    Go to **PostHog → Settings → Project → Privacy → IP data capture configuration** and
    enable the option to discard client IP data.

    **2. Automatic-capture toggles — acknowledgement only.**
    The adapter disables the remote-configuration fetch, so a project-UI toggle for heatmaps,
    web vitals, exception capture, session replay, or surveys cannot silently take effect.
    Re-enabling that fetch would be the single change that breaks the guarantee. No action is
    required.

    This checkpoint stops for a human in every mode, including unattended runs, because a
    privacy control the code cannot assert must never be auto-approved into the record.
  </instructions>
