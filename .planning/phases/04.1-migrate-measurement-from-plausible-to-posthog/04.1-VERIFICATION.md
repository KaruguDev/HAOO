## Verdict in one line

**Both prior gaps are genuinely closed, and I proved the closure by running the real vendor SDK rather than by reading the code or the SUMMARYs** — a configured adapter now returns a working sink, exactly one request leaves the page, and it carries one bare allowlisted event name with exactly three transport properties and no browser storage at all. That is an owner action, not a code defect, and this report refuses to round it up.

## What I did NOT take on trust

The three SUMMARYs claim delivery is wired. Every test in this repository exercises a **fixture** transcription of the vendor (`src/test/fixtures/posthog-capture-contract.ts`), never the real SDK — the previous verification recorded that fidelity gap as WR-F (20 documented default keys against 33 asserted). So the central claim of this round was, in-repo, unproven in exactly the place it mattered. I ran the real thing.

**Probe A — does the REAL posthog-js 1.425.1 merged config satisfy `lockdownHolds`?**
Imported the pinned module in jsdom with `fetch`/`XMLHttpRequest`/`sendBeacon` patched before import, called `posthog.init(token, POSTHOG_LOCKDOWN(...))`, read `instance.config`, ran `lockdownHolds`.

```
{ "threw": null, "hasConfig": true, "lockdownHolds": true, "mismatches": [], "netCalls": [] }
```

The 33-key readback — including `before_send` **by identity** — holds against the real vendor, not only the fixture. This is the single most load-bearing fact in the phase and nothing in the repository asserted it.

**Probe B — what actually leaves the page for one allowlisted capture?**
Same setup, `apiHost` pointed at `http://127.0.0.1:9` so nothing could reach a real endpoint, drove `sink('haoo_page_view')` and `sink('not_allowlisted_event')`, waited for the vendor's batch flush.

```json
{ "kind": "fetch", "url": "http://127.0.0.1:9/e/",
  "parsed": { "api_key": "phc_probeLocalOnly",
    "batch": [ { "uuid": "01a06ea0-...", "event": "haoo_page_view",
        "properties": { "token": "phc_probeLocalOnly",
                        "distinct_id": "01a06ea0-...",
                        "$process_person_profile": false } } ] } }
```

**One** request. **One** event. The bare allowlisted name. Exactly the three transport properties. The non-allowlisted name was dropped by the reducer and never appeared. No `$pageview`, `$pageleave`, `$autocapture`, `$rageclick`, `$web_vitals` or `$exception` accompanied it. `$process_person_profile: false` — the never-create-a-profile channel — is present in the envelope that actually leaves.

**Probe C — real-SDK browser storage footprint.**

```
{ "localStorageKeys": [], "sessionStorageKeys": [], "cookie": "" }
```

Zero. The `persistence: 'memory'` + `disable_persistence: true` pair behaves against the real vendor as the fixture-based regression claimed, and `distinct_id` is a per-page-load UUID rather than a persisted identifier — which is also what makes the disclosure sentence "a temporary reference that lasts only for the current page load" literally accurate.

**Probe D — the second-initialization question (review WR-01), untested in either direction.**

```

  "reasons": ["posthog:unconfirmed-lockdown-readback"] }
stderr: [PostHog.js] You have already initialized PostHog! Re-initializing is a no-op
```

WR-01 is **confirmed by measurement**, not merely plausible. See the warning below.

All probe files were removed; `git status --porcelain -- src` is empty and no `dist-*probe*` directory survives.
