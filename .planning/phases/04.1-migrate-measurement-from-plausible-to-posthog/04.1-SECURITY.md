## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| npm registry → repository | Third-party packages (`posthog-js`, `@posthog/wizard`) enter build inputs and the published bundle | Executable code |
| built bundle → public internet | Every asset under `dist/assets` is world-readable | Application source, build-time constants |
| browser → PostHog ingestion | Visitor actions emitted as named events to `us.i.posthog.com` | Event name only (no person profile, no automatic capture) |
| browser → local storage | Client-side persistence surface the SDK could write to | Phase 3 engagement-context key only |
| owner workstation → PostHog Query API | Local report script issues an authenticated HogQL query | Personal API key (Query Read scope), aggregate counts |
| PostHog project settings → ingestion | Server-side enrichment the codebase cannot observe or assert | Geo-derived properties (owner-suppressed) |

### 2026-09-05 — plan 04.1-10 restates T-04.1-02 and T-04.1-14

**Both rows' earlier `closed` verdicts were premature.** They were recorded at the
2026-09-04 ASVS L1 audit, before `04.1-VERIFICATION.md` (verified 2026-09-04T00:04:08Z,
`status: gaps_found`) adjudicated code-review blocker CR-02 as CONFIRMED and traced what
the mitigations did not cover. The mitigation text above has been restated against what
the code now does; the original text is preserved verbatim here so nothing is lost.

| Row | Verdict as recorded 2026-09-04 | Why it was premature |
|---|---|---|
| T-04.1-02 | severity `high`, mitigation: "`autocapture: false`, `rageclick: false`, closed event-name allowlist in `before_send`, freshly-built three-key properties literal — two independent layers (`posthog-lockdown.ts:101-128`)" | True but incomplete. The 33rd locked key — `before_send`, the chokepoint itself — was asserted `typeof merged.before_send === 'function'` while all 32 others compared against literals. A client that echoed back the configuration object it was handed while substituting its own reducer passed every check. The suite could not see the hole: the per-key hostile table's `before_send` row substituted a NON-function, which the `typeof` guard refuses before identity is ever consulted. |
| T-04.1-14 | severity `medium`, mitigation: "Decide-before-assign: a defined-but-not-object-with-callable-`init` global is refused intact, never overwritten and never initialized (`posthog.ts:26,130`)" | The refusal half was genuine and well tested. The ACCEPT half was not stated at all: a value exposing a callable `init` was ADOPTED, which is the exact property a hostile global is free to expose. `medium` understated it, because the consequence is a disclosure, not merely a spoof. |

**Severity raised: T-04.1-14 `medium` → `high`.** The disposition stays `mitigate`. The
verifier traced the consequence precisely: an adopted global receives the public project
key and the ten bare first-party event names in real time, with whatever properties it
chooses to attach — while `MeasurementDisclosure.tsx` renders a sentence naming PostHog in
the United States as the SOLE processor of that data (D-10, MEAS-04's factual basis). A
threat whose realization makes a rendered privacy disclosure untrue is not a medium.
Because of gap `G-04.1-1` (no production module loaded the SDK until `04.1-09`) the adopted
branch was, in production, reachable ONLY by a value some other party put on `window`.

**What closes them now.**

- T-04.1-14 — `resolveClient` has no adoption branch (`src/measurement/posthog.ts:273-277`);
  every occupied slot refuses. Proven by `measurement.test.ts:1103` (CR-02, both halves),
  three added `hostileSlotRows` rows, one added journey row, and mutation probe 1, which
  restored adoption and observed five cases red.
- T-04.1-02 — the identity comparison landed in commit `33deb5a` before this plan and is
  CONFIRMED rather than re-implemented here: the expectation carries the retained
  `lockdown.before_send` (`posthog.ts:374`), the readback compares by identity
  (`posthog-lockdown.ts:290`), and the derived per-key hostile table substitutes a callable
  reducer. Mutation probe 2 replaced the identity comparison with a type-only check and
  observed two cases red. What `04.1-10` adds is that the merged configuration is no longer
  supplied by a client this repository did not choose.

**Both closures are falsifiable, and were falsified on purpose.** The two probes and their
observed failure messages are recorded in `04.1-10-SUMMARY.md`; both mutations were
restored with `git checkout --` and `git status --porcelain -- src` was empty afterwards.
