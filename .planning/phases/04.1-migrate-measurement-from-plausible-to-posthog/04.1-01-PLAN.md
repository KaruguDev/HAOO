<objective>
Make the repository able to hold a bundled analytics SDK without silently invalidating a
Phase 4 guarantee, and pin PostHog's capture payload shape with an independent fixture.

`src/test/build-output.test.ts:203` forbids the literal `posthog` in every built asset and
every production source file, and `builtBundleText()` concatenates every `.js` under
`dist/assets` — so installing the SDK breaks `npm test` immediately. That prohibition is
withdrawn here **deliberately and with a named successor** (04-08's delivery-mechanism
guarantee), never by deletion.

Purpose: unblock the tracer in 04.1-03 while keeping every claim the boundary suite makes
true and falsifiable.
Output: a restated boundary suite, its derived reader in the report suite, and the new
vendor-contract fixture that replaces the Plausible preload fixture.
</objective>

    - `VendorPostHogConfig` — the merged-config readback surface, typed as
      `Record<string, unknown>`, since the adapter must inspect it structurally rather than
      trust a declared type.
    - `VendorPostHogInstance` — `{ config: VendorPostHogConfig; capture(event: string): void }`.
    - `VendorPostHogClient` — `{ init(token: string, config?: Record<string, unknown>): VendorPostHogInstance }`.

    - `installPostHogVendorClient(scope, overrides?)` — returns a `VendorPostHogClient`

      merged result to `instance.config`, records every `capture` call and every payload
      that survives the configured `before_send`, and returns the instance without throwing
      on a blank token. `overrides` lets a test force a single resolved key to a wrong
      value so the adapter's readback refusal can be exercised.
    - Exported inspection helpers on the returned client: the recorded initialization
      config, the ordered list of captured event names, and the ordered list of payloads
