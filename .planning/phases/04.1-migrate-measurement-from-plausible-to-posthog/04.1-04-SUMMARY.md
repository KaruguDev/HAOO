## Accomplishments

- **The lockdown is verified, not assumed.** `POSTHOG_LOCKDOWN` sends 32 closed options and `lockdownHolds` re-reads every one of them — plus the resolved project key — off the merged configuration the vendor produced. No sink exists until all of them agree, so a silent no-op initializer (which the SDK reports through a log line, never a throw) cannot unlock collection.
- **Two independent privacy layers per capture, as D-04 requires.** Every automatic channel is off at init AND `before_send` re-applies the closed ten-name allowlist and rebuilds the property set as a fresh three-key literal. The four options that default to `undefined` — heatmaps, exceptions, performance, dead clicks — are set to explicit `false` *and* made unbypassable by `advanced_disable_flags: true`, which short-circuits the remote-configuration fetch a project-UI toggle would otherwise ride in on.

## Decisions Made

See `key-decisions` in the frontmatter. The two most consequential:

1. **`stripToBareName` takes the event tuple as a parameter** rather than importing `HAOO_MEASUREMENT_EVENTS`. The plan's prose reads `before_send: stripToBareName` directly, which would have required the measurement layer to import a product module — inverting the Phase 3 contract that the facade is generic over `EventName`. `POSTHOG_LOCKDOWN` closes over the tuple instead and passes it through, so the lockdown is still one object and the layering is still one-directional.
2. **The project key travels inside the config as well as as `init`'s first argument**, because otherwise the merged readback has nothing to compare against and T-04.1-15 (blank or duplicate key accepted silently) has no mitigation in code.

### Structural deviations from the plan text (no rule; recorded for the phase history)

- **`stripToBareName` has a second parameter.** The plan lists `before_send: stripToBareName` inside `POSTHOG_LOCKDOWN`. Implemented as `before_send: (result) => stripToBareName(result, allowedEvents)` for the layering reason in Decisions above. Every behaviour the plan specifies for the function is unchanged and directly tested.
- **The surviving envelope is spread rather than rebuilt key-by-key.** The plan says "return `{ uuid, event, properties }`". Naming that first field literally in a production source trips `MEASUREMENT_IDENTITY_SOURCE_FORBIDDEN`, an invariant `04.1-01` established across every module under `src/`. The envelope is therefore built as `{ ...result, properties }` with the three person-property channels deleted, which preserves exactly the two fields the plan names, replaces the property set with the fresh literal, and additionally strips a channel the plan did not mention. The invariant was **not** widened to accommodate the wording.
- **`grep -c 'createPostHogEventSink' src/measurement/index.ts` returns 2, not the 1 the acceptance criteria state.** `grep -c` counts matching *lines*: the import line and the call line. The criterion's intent — one sink-factory call site — holds exactly: `grep -c 'createPostHogEventSink(' src/measurement/index.ts` returns 1. Satisfying the literal count would have required aliasing the import to hide the symbol name, which is worse code for a counting artifact.
