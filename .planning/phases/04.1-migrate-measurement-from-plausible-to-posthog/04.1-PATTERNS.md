## Pattern Assignments

### `src/measurement/posthog.ts` (adapter, event emission) — NEW

**Analog:** `src/measurement/plausible.ts` (241 lines, read in full)

**Copy this file's five-part structure verbatim in order:** (1) exported option/global/scope/adapters
types with the privacy rationale in the doc comment, (2) `resolveX(adapters)` helpers wrapping every
ambient global in `try { adapters.x ?? window.x } catch { return null }`, (3) a decide-before-assign
resolver for any pre-existing global, (4) a confirmation predicate on untrusted readback, (5) the
exported `create*EventSink` returning `undefined` on every unconfirmed path.

**Adapters-injection pattern** (`plausible.ts:31-61`) — copy shape exactly:

```ts
export interface PlausibleScope { plausible?: PlausibleGlobal; }

export interface PlausibleAdapters {
  readonly documentRef?: Document;
  readonly scope?: PlausibleScope;
}

function resolveScope(adapters: PlausibleAdapters): PlausibleScope | null {
  try {
    return adapters.scope ?? (window as unknown as PlausibleScope);
  } catch {
    return null;
  }
}
```

PostHog equivalent adds a `client?: { init(...) }` member (tests never load a real SDK) and a
`signalRefusal?: (reason: string) => void` member for D-05. Keep the `?? window.x` inside `try`.

**Adopted-versus-installed decision** (`plausible.ts:150-185`) — this is the 04-12 rule and the
PostHog adapter needs the exact equivalent. Note the comment density: each refusal branch carries
the reason it refuses rather than restoring state.

```ts
function resolveInitializedProvider(
  scope: PlausibleScope,
  options: PlausibleInitOptions,
): PlausibleGlobal | null {
  const existing = scope.plausible;

  // Decide before assigning. A defined value that is not callable ... carries no way to
  // establish the opt-out, and overwriting somebody else's global is not this adapter's to do.
  if (existing !== undefined && typeof existing !== 'function') return null;

  const provider = existing ?? installProviderStub(scope);
  if (typeof provider.init !== 'function') return null;

  try {
    provider.init(options);
    if (!recordsOptOut(provider.o, options.domain)) return null;
  } catch {
    // A throwing initializer leaves the opt-out unproven ... Refuse rather than guess.
    return null;
  }

  return provider;
}
```

**Confirmation-on-untrusted-readback pattern** (`plausible.ts:125-130`) — this is the direct
ancestor of RESEARCH's `lockdownHolds(instance.config)`. Copy the structural-inspection style
(`typeof !== 'object' || null` guard, then explicit per-key equality, never a type assertion):

```ts
function recordsOptOut(recorded: unknown, domain: string): boolean {
  if (typeof recorded !== 'object' || recorded === null) return false;

  const candidate = recorded as Partial<PlausibleInitOptions>;
  return candidate.autoCapturePageviews === false && candidate.domain === domain;
}
```

**Fail-closed sink creation + ordering** (`plausible.ts:205-241`) — the ordering here IS the privacy
contract and must be preserved: provider check → config emptiness check → capability resolution →
confirmed opt-out → *only then* side effect → return sink.

```ts
export function createPlausibleEventSink<EventName extends string>(
  config: Pick<ProductMeasurement<EventName>, 'provider' | 'providerScript'>,
  adapters: PlausibleAdapters = {},
): ((event: EventName) => void) | undefined {
  if (config.provider !== 'plausible') return undefined;

  const providerScript: MeasurementProviderScript = config.providerScript;
  if (providerScript.src === '' || providerScript.domain === '') return undefined;

  const scope = resolveScope(adapters);
  const documentRef = resolveDocument(adapters);
  if (scope === null || documentRef === null) return undefined;

  const provider = resolveInitializedProvider(scope, {
    domain: providerScript.domain,
    autoCapturePageviews: false,
  });
  if (provider === null) return undefined;

  appendProviderScript(documentRef, providerScript.src);

  return (event: EventName) => {
    try {
      const provider = scope.plausible;
      if (typeof provider !== 'function') return;
      provider(event);
    } catch {
      // Provider delivery is deliberately isolated from every visitor action.
    }
  };
}
```

For PostHog: `appendProviderScript` disappears (bundled SDK), `init` is `client.init(token, LOCKDOWN)`,
`recordsOptOut` becomes `lockdownHolds(instance.config)`, and each `return undefined` on the
post-init paths additionally calls `signalRefusal(reason)` (D-05). The returned sink stays
one-argument, name-only, try/catch-wrapped — the single-parameter signature is what makes a property
bag structurally impossible.

**Error-handling pattern:** there is no thrown error anywhere in this module. Every failure is
`return null` / `return undefined` / swallowed `catch` with a comment naming why swallowing is
correct. Do not introduce throws or logging beyond the D-05 refusal channel.

### `src/reporting/stats-response.ts` (validator, transform) — MODIFY row shape only

**Analog:** itself, `parseGoalCounts` lines 22-56 (read in full).

Every rejection rule is preserved byte-for-byte; only the two shape checks at lines 35-36 change.

```ts
export function parseGoalCounts(
  body: unknown,
  allowedGoals: readonly string[],
): Readonly<Record<string, number>> | null {
  try {
    if (!isPlainObject(body)) return null;
    if (!Array.isArray(body.results)) return null;

    const allowed = new Set(allowedGoals);
    const seen = new Map<string, number>();

    for (const row of body.results) {
      if (!isPlainObject(row)) return null;
      if (!Array.isArray(row.dimensions) || row.dimensions.length !== 1) return null;   // ← changes
      if (!Array.isArray(row.metrics) || row.metrics.length !== 1) return null;         // ← changes

      const goal = row.dimensions[0];
      if (typeof goal !== 'string' || !allowed.has(goal)) return null;
      if (seen.has(goal)) return null;

      const count = row.metrics[0];
      if (typeof count !== 'number' || !Number.isInteger(count) || count < 0) return null;

      seen.set(goal, count);
    }

    const counts: Record<string, number> = {};
    for (const goal of allowedGoals) counts[goal] = seen.get(goal) ?? 0;
    return counts;
  } catch {
    return null;
  }
}
```

> assert `columns` equals the exact expected pair so a reordered projection cannot swap name and
> count. Note the header comment names the threat (`T-04-04`) and the template it follows
> (`parseContext` in `src/measurement/index.ts`) — keep both references current.

## Shared Patterns

### Fail closed by returning a sentinel, never by throwing
**Source:** `src/measurement/plausible.ts` (every branch), `src/reporting/stats-response.ts:22-56`,
`src/products/haoo.ts:51`
**Apply to:** every new adapter, validator, and resolver in this phase.
Refusal values are `undefined` (no sink), `null` (no parse / no provider), `''` (no source), or
`{ok:false, reason}`. `try { … } catch { return <sentinel> }` wraps every untrusted or ambient
interaction. No `throw` in browser-reachable code.

### Untrusted input is inspected structurally, never trusted to its declared type
**Source:** `plausible.ts:125-130`, `stats-response.ts:27-43`, `query-provenance.ts` (`isPlainObject`)
**Apply to:** the lockdown readback, the HogQL response reader, the echo validator.
Guard `typeof x !== 'object' || x === null` first, check every field explicitly, and rebuild a fresh
literal rather than spreading the untrusted record.

### Injected capabilities so tests never touch a real global, document, network, or SDK
**Source:** `plausible.ts:31-61` (`adapters.x ?? window.x` inside `try`),
`generate.ts` (`fetch`, `now`, `fs` all injected)
**Apply to:** `posthog.ts` (`scope`, `client`, `signalRefusal`), the report query path.

### Environment variables may only *select from* repository-owned configuration
**Source:** `config/approved-analytics-script-sources.ts:1-18`, `haoo.ts:51,110`
**Apply to:** every new `VITE_*` / `POSTHOG_*` name introduced. A public variable never supplies a
value the repository has not already approved, and the runtime re-validates what the build selected.

### Comments carry the reasoning, and name the artifact that settles what code cannot prove
**Source:** `plausible.ts:104-130` and `fixtures/plausible-preload-contract.ts:17-28` — both point at
`04-USER-SETUP.md` for the live human gate
**Apply to:** every PostHog refusal path and the new contract fixture. This is the 04-13 rule: state
what a check actually proves, and route the unprovable remainder to a named human gate.

### Credential isolation
**Source:** `scripts/generate-haoo-report.mjs:80-97` (only credentialed module) and
`generate.ts:200-206` doc comment (key in the `Authorization` header only)
**Apply to:** the PostHog personal API key. Asserted by `haoo-report.test.ts:1059` and by
`REPORT_CREDENTIAL_BUNDLE_FORBIDDEN` in `build-output.test.ts:207`.

### One bare event name, no property parameter
**Source:** `plausible.ts:231-240` (sink signature `(event: EventName) => void`),
`measurement/index.ts` `track(event: EventName)`
**Apply to:** the PostHog sink. The absence of a second parameter is the enforcement mechanism;
property stripping in `before_send` is the second, independent one.
