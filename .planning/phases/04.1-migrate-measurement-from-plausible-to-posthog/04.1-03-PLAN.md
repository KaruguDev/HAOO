<objective>
Get the pinned PostHog SDK into the repository under a legitimacy gate, and plant the
repository-owned ingestion-host trust anchor the tracer will consume — without touching a
single line of the runtime measurement path.

These are the two parts of the migration that are genuinely **off** the runtime path the
tracer proves. The tracer test injects its client and constructs its config directly, and
the build-time constant is deliberately absent under the test runner — so neither the
install nor the define can be exercised by an end-to-end runtime test. They are proven by a
package check and by the bundle-level boundary suite instead, which is why they are split
out here rather than carried inside the tracer slice.

Everything in this plan is **additive**. The superseded Plausible configuration module, its
define, and its two environment-variable declarations all survive this plan untouched,
because `src/products/haoo.ts` still reads them and will until `04.1-04` replaces its
resolvers. That is what keeps the repository typechecking and the suite green at every
commit; `04.1-04` removes the readers and what they read in the same commit.

Purpose: separate the install and the build-time trust anchor from the runtime slice so the
tracer stays one coherent end-to-end task instead of an eight-layer omnibus.
Output: a pinned `posthog-js`, `config/approved-analytics-hosts.ts`, its provider-gated
define, its type declarations, and the boundary assertions that hold it.
</objective>

  <what-built>
    Nothing yet — this checkpoint runs before any package enters the lockfile.

    The package-legitimacy audit in `04.1-RESEARCH.md` returned `[SUS] too-new` for both
    packages this phase needs. Honest reading of the verdicts: both exist, neither is
    deprecated, both declare no postinstall script, both carry official PostHog source
    repositories, and `posthog-js` has ~12.7M weekly downloads. The `too-new` signal is
    triggered by the *latest version's* publish date, which is an artifact of PostHog's
    release cadence rather than evidence of slopsquatting — but a same-day release is a
    release nobody has run in anger, which is a real risk surface for this project
    specifically.

    | Package | Registry | Verdict | Repo |
    |---|---|---|---|
    | `posthog-js@1.425.1` | npm | `[SUS] too-new` (published 2026-09-02) | github.com/PostHog/posthog-js |
    | `@posthog/wizard@2.71.0` | npm | `[SUS] too-new` (published 2026-09-01) | github.com/PostHog/wizard |

    This checkpoint is emitted mid-flight despite `workflow.human_verify_mode = end-of-phase`
    because a package-legitimacy gate is never auto-approvable: verifying a dependency
    after it is already installed and executed defeats the gate.
  </what-built>

       points at github.com/PostHog/wizard.
