## Decisions Made

- **Adoption was removed, not tightened.** A stricter structural check (require `capture`
  too, require a `_i` internal, require the vendor's own prototype) would have been the
  smaller diff and would have been worthless: every one of those is a property a hostile
  global can be written to expose. The question the gate now asks is provenance — did this
  repository choose this value — which is the only question a page cannot answer for it.
- **Five cases moved to the seam rather than collapsing.** See the finding below.
- **The occupying installer stays.** It has zero callers and is dead by design. It is the
  fixture's only executable transcription of how a real vendor snippet claims the global
  name, which is precisely the shape the refusal is a claim about; deleting it would remove
  the statement of what is being refused.
- **The page journey samples at `init`, not at the slot read.** `init` is the strictly
  later of the two moments and is still strictly before a sink exists, which is exactly
  what the case's own doc comment claims, so the ordering assertion is preserved in
  substance.

**1. [Finding — reported, not adjusted] The ambient-slot-literal count is 9, not the 13 the plan states**

The plan's Task 2 acceptance criterion states: *"Before this task there are 12 in
`measurement.test.ts` and 4 in `measurement-page.test.tsx` … After this task the counts are
13 and 4."* It then instructs: *"Any other delta is a finding to report, not a number to
update."* This is that report.

- **Before:** 12 in `measurement.test.ts` (confirmed by measurement — `grep -c "posthog:"`
  returns 13, minus the `/^posthog:[a-z-]+$/` refusal-reason regex the plan excludes) and 4
  in `measurement-page.test.tsx`. **Both match the plan exactly.**
- **After:** **9** and **4**. The page file matches; `measurement.test.ts` is four below the
  stated 13.

**Why.** The plan's list names each surviving literal and requires that each "expects a
refusal". Five of the twelve do not merely expect *a* refusal — they expect a refusal from a
**later gate**, reached only because adoption let a well-formed ambient value through:

| Literal | Gate it proved | Post-Task-1 reality if left on the slot |
|---|---|---|
| `refuses, without throwing, when the initializer throws` | `initialization` | `foreignClient` — the only coverage of the initialization gate is lost |
| `unreadableInstanceRows` (5 rows) | `lockdown`, on five distinct return shapes | `foreignClient` on all five — a five-row table becomes five copies of one assertion |
| `refuses an initialized instance whose capture entry point is not callable` | `absentCapture` | `foreignClient` — the only coverage of the last gate before a sink is lost |
| journey row `the initializer throws` | `initialization` at journey level | duplicate of journey row 1 |
| journey row `the initialized instance exposes no capture entry point` | `absentCapture` at journey level | duplicate of journey row 1 |

Leaving them on the slot would have satisfied the count while retiring three refusal
reasons from the suite — which the plan's own transparency prohibition forbids by name, and
which is the exact failure the count exists to catch. The count was therefore missed
deliberately rather than met vacuously.

**Full reconciliation (12 − 5 + 2 = 9):**
