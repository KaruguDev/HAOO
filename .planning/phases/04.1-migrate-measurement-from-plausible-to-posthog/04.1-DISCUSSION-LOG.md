## Automatic-Capture Posture

### Q1 — How the PostHog client reaches the page

| Option | Description | Selected |
|--------|-------------|----------|
| Keep the script-insertion seam | Insert PostHog's hosted `array.js` from a repo-owned approved origin, preserving `config/approved-analytics-script-sources.ts` and the 04-08 origin constraint. | |
| Bundle `posthog-js` as a dependency | npm install and import; removes the approved-origin allowlist concept and the "no analytics in an unconfigured build" guarantee. | |
| Bundle it, but lazy-import | Dependency behind a dynamic `import()` gated on provider resolution and confirmed opt-out. | |

**User's choice:** Free text — "use this `npx -y @posthog/wizard@latest`"
**Notes:** This is effectively the bundled-dependency path, seeded by PostHog's setup wizard rather
than hand-written. Concern raised and recorded: the wizard wires PostHog's defaults (autocapture on,
`$pageview` on, cookie persistence) — exactly the behaviours Q2 requires off — and has no knowledge
of the repository's fail-closed provider seam. Resolved in the next area's Q1: the wizard scaffolds,
then its output is conformed to the seam.

### Q2 — Which automatic behaviours must be provably off (multi-select)

| Option | Description | Selected |
|--------|-------------|----------|
| Autocapture (clicks/inputs/forms) | Records DOM interactions including form fields; violates the closed allowlist and MEAS-02. | ✓ |
| Automatic `$pageview` / `$pageleave` | Emits events outside the allowlist and duplicates `haoo_page_view`. | ✓ |
| Session recording (replay) | Raw session replay; violates MEAS-03's no-raw-clickstream rule. | ✓ |
| Surveys, heatmaps, exception capture, web vitals | Remaining capture surfaces; locking them explicitly prevents a default change re-enabling one. | ✓ |

**User's choice:** All four
**Notes:** None.

### Q3 — How the opt-out is proven (the 04-09 gate)

| Option | Description | Selected |
|--------|-------------|----------|
| Network-level: only allowlisted names leave | Assert on captured request payloads; survives version bumps. | |
| Config-object assertion | Assert init options before insertion; deterministic but proves intent, not behaviour. | |
| Both, as separate gates | Config assertion fails closed at runtime; network regression catches upstream drift. | ✓ |

**User's choice:** Delegated — "choose the most appropriate choice"
**Notes:** Selected *both*, with rationale given to the user: with a bundled SDK the config assertion
is what keeps 04-09 failing closed in production, while the network test catches a PostHog version
bump re-enabling something. Phase 4 required three gap-closure rounds on this class of drift.

### Q4 — Failure posture when the lockdown cannot be established

| Option | Description | Selected |
|--------|-------------|----------|
| Refuse: no init, no event sink | Fail closed as 04-09 and 04-12 do today. | |
| Refuse and surface it to the owner | Fail closed, and make the refusal detectable rather than silent. | ✓ |
| You decide | Leave signalling to research and planning. | |

**User's choice:** Delegated — "choose the most appropriate choice"
**Notes:** Selected surface-to-owner, with rationale: a silently refusing bundled SDK produces a
report reading as zero traffic, indistinguishable from a genuinely dead funnel.
