# Deleted provider test cases — `04.1-04` → `04.1-05` hand-off

**Closed by `04.1-05` Task 3 on 2026-09-03. Every row is `restored`; the
`## Deliberately not restored` section is empty. The interval in which this repository
ran with reduced provider test depth was exactly one wave.**

The tracer slice (`04.1-04`) removed the Plausible adapter and every test case written
against it. The six provider describes in `src/test/measurement.test.ts` survived at
**tracer depth only** for exactly one wave: each kept a single migrated PostHog case so
the describe still asserted something, and everything else listed below was gone until
`04.1-05` restored it at full depth.

This file — not the `04.1-04` SUMMARY prose — is the authority on that reduction.
`04.1-05` Task 3 closes it out and fails while any row still reads `pending`.

**How to read a row.** `Case` is the exact `it(...)` title as it stood before deletion.
`Restored by` names the `04.1-05` task that owns its PostHog successor. `Successor` names
the describe — and, where the deleted case has no one-to-one analogue under a bundled SDK,
the specific case — that now carries the guarantee. `Status` is `restored` for every row.

**On the three rows whose mechanism no longer exists.** Plausible was fetched as a
script; PostHog is bundled (D-02). "Appends the site script exactly once", "the preload
options and event-queue contract" and "the provider script load fails" therefore have no
literal successor — there is no script tag to append, no preload queue to drain, and no
script load to fail. Each is restored as the guarantee it existed to protect, not as the
mechanism it happened to assert: initialize-exactly-once, the vendor-documented-defaults
readback, and journey survival when the provider is unusable. The mapping is stated per
row rather than left implicit, because a silently re-pointed row is how a coverage
reduction hides inside a migration.
