**The owner report now produces the same four literal count sets from a HogQL aggregate per range with the reporting timezone pinned inside the query text, keeps every prior refusal and adds a column-pair refusal, and states in its own rendered words the one provenance guarantee PostHog cannot supply.**

## Accomplishments

- **The row reader reads positional HogQL rows without losing a rule.** `parseGoalCounts` now asserts `columns` equals `['event', 'occurrences']` for exact equality before the row loop, then reads each row as a two-element positional array. The allowlist check, the duplicate check, the integer / finite / non-negative checks, the zero-fill pass, the fresh-literal rebuild and the `try`/`catch` returning `null` are all preserved. The column assertion is the new refusal: a reordered projection would otherwise swap the name and the count and parse cleanly into ten believable integers attached to the wrong actions.
- **Provenance became one exact-SQL equality.** `validateEchoedQuery` accepts a response whose echoed query equals the submitted SQL byte-for-byte, in either documented echo shape, and refuses everything else. That single check subsumes the metrics, dimensions, filter and date-range checks the previous provider needed, because the SQL text carries the event allowlist and both range bounds. Whitespace is deliberately not normalised: the submitted text is repository-owned and byte-stable, so a difference is evidence.
- **The timezone moved from a remote setting into the query.** `haooFunnelSql` converts each event timestamp into `Africa/Nairobi` inside the SQL and compares both bounds inclusively as whole days. The provider can no longer disagree with the report about a day boundary, so the timezone-mismatch failure mode is retired — its rejection union member, its exported reason prefix, its offset-parsing helper, its failure mapping and its terminal sentence are all gone, each with the removal reasoned in place in the voice of the comment it replaced.
- **The all-time first recorded day is asked for, not inferred.** The previous provider echoed the range it resolved for an open-ended query; this one does not. A separate single-value query now resolves the first recorded day, and a response that is neither zero rows nor exactly one single-element ISO day aborts the run. One run is now eight requests: six bounded aggregates, the unbounded all-time aggregate, and the first-day query.
- **The report says what it can no longer prove.** Two authored sentences were appended to `REPORT_CAVEATS`: that all-time counts begin at the first action recorded for this project because there is no earlier provider history to include, and that the provider echoes the query this report submitted but not the project that answered it — so the metadata line names the project the command was configured with, not one the response proved. Both are pinned by exact text against an independently authored copy in the suite.
- **A stale environment names its own rename.** The CLI carries a removed-variable table checked for presence rather than absence. An environment still holding a credential under a previous-provider name is told which name replaces it, instead of being told the new name is missing — which would have sent the owner to create a credential they may already hold.

## Decisions Made

- **Eight requests, not seven.** The plan's behaviour required a separate first-day query. Rather than running it conditionally on a non-zero all-time total, it runs unconditionally so the request sequence is deterministic and the fixture can pin it exactly.
- **A malformed first-day answer aborts the whole run** rather than degrading to an unnamed heading. A silently dropped refusal would hide a response the report did not understand, and a wrong first day is a claim the report cannot support.
- **`min(timestamp)` returning a provider default rather than zero rows is self-correcting.** The resolved day is only ever used when the all-time total is non-zero; a zero total renders the empty-state heading regardless. This is recorded in `parseFirstRecordedDay`'s docblock.
- **The removed-variable table names the two browser variables as well as the two report variables,** even though this command never reads them: an environment carrying either is an unmigrated shell or CI configuration, and saying so once here is cheaper for the owner than discovering it at deploy time.
