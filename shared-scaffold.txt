# shared-scaffold.txt — the closed list of paths that legitimately exist in BOTH
# `KaruguDev/ZERO-PAPERHUB` and `KaruguDev/HAOO`.
#
# TWENTY-SIX ENTRIES, ON TWO DIFFERENT GROUNDS. The distinction is load-bearing and is
# marked machine-readably by the `# @ground:` directives below. Do not collapse it.
#
# WHY THIS FILE EXISTS
# SPLT-01 says HAOO builds, tests and deploys from a repository containing no ZERO-PAPER
# HUB source, and ZERO-PAPER HUB from one containing no HAOO source, with neither suite
# reading a file the other owns. Taken as a claim about PATHS that is unsatisfiable: both
# repositories legitimately carry the same toolchain, and both descend from the same Vite
# React scaffold. Toolchain scaffolding is owned by NEITHER half — it is owned by the
# repository. A check that treats these paths as violations fails for the WRONG REASON,
# and a check that fails for the wrong reason gets disabled. So this list is not a
# loophole; it is the thing that makes the requirement mean something.
#
# THE RULE FOR ADDING AN ENTRY — THIS LIST IS CLOSED
# An entry is added on exactly one of the two grounds below, and NEVER because "both
# halves need it". A product file the other half also needs is precisely the coupling
# SPLT-01 exists to forbid: it is a VIOLATION, not an allowlist candidate. Never add a
# path here to make a failing run pass.
#
# (Modelled on the closed-list discipline documented at
# `src/test/focus-contrast.test.ts`, where the list is kept closed by registering each
# new component rather than by widening the token set, so a style that is never measured
# cannot ship.)
#
# EVERY ENTRY SUBTRACTED IS A PATH THE CHECK STOPS GUARDING.
# `scripts/verify-tree-disjointness.mjs` prints how many entries it subtracted on every
# run, so growth in this list is visible in the recorded output rather than silent.
#
# BYTE-IDENTICAL IN BOTH REPOSITORIES. A private definition of "shared" in one repository
# is the first step to the two trees disagreeing about what separation means, so a
# unilateral widening shows up as a `cmp`. (T-04.2-40.)
#
# Source of truth: `.planning/phases/04.2-split-haoo-into-its-own-repository-and-domain/
# 04.2-SPLIT-CONTRACT.md` § "Shared scaffold". Change them there and here together.
#
# Blank lines and lines beginning with `#` are ignored by the reader. Everything else is
# one bare repository-relative path, matched by EXACT WHOLE-LINE comparison — never as a
# glob, a prefix or a substring. A path fragment match would forgive an unrelated file
# that merely contains an allowlisted name, and would flag
# `public/products/haoo/index.html`, which exists in ZERO-PAPER HUB only.

# ─────────────────────────────────────────────────────────────────────────────────────
# @ground: collision
#
# GROUND B — RATIFIED PATH COLLISIONS WITH DIVERGENT CONTENT (3 entries)
#
# These are NOT shared files. They are the same PATH holding entirely different content,
# because both repositories descend from the same Vite React scaffold. ZERO-PAPER HUB's
# `src/App.tsx` contains ZERO-PAPER HUB source; HAOO's contains HAOO source. Neither tree
# contains the other's source, so SPLT-01's actual claim — which is about CONTENT
# OWNERSHIP, not path occupancy — is satisfied. Ratified by the owner on 2026-09-06 on
# that ground, which is DIFFERENT from Ground A's.
#
# ⚠ HOW THIS GROUND DECAYS, AND WHAT IS DONE ABOUT IT
# A Ground A entry is safe indefinitely: the two copies being identical is the point. A
# Ground B entry is safe only while the two copies stay DIVERGENT. If the content of one
# of these three ever CONVERGES — one repository's copy edited to match the other's —
# that is a genuine SPLT-01 violation, and a plain path allowlist would be blind to it,
# because the path is on the list either way.
#
# So the auditor does not merely subtract these three: it asserts, per entry, that the
# two copies are NOT byte-identical, and reports convergence as a violation. That turns
# the decay risk into a checked property rather than a comment nobody re-reads. A Ground
# B entry that becomes identical across the two repositories FAILS the run.
#
# Consequently: never move an entry between the two grounds to silence a finding. Moving
# a converged file from Ground B to Ground A would declare a genuine violation to be
# scaffolding, which is the one thing this file's rule forbids.
# ─────────────────────────────────────────────────────────────────────────────────────
